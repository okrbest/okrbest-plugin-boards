# Contract: 카드 속성 패치 관문

**Spec**: [spec.md](../spec.md) | FR-005~FR-011

## 대상 경로

카드 속성을 바꿀 수 있는 요청 경로 전부. 조회 결과 둘이다(R1).

| # | 경로 | 이 경로로 오는 조작 |
|---|---|---|
| P1 | `PATCH /api/v2/boards/{boardID}` | 속성 추가, select·multiselect 옵션 편집 |
| P2 | `PATCH /api/v2/boards-and-blocks` | 속성 삭제, 속성 유형 변경 |

두 경로 모두 같은 판정을 한다. **P2를 빠뜨리면 속성 삭제와 유형 변경이 통과한다.**

## 판정

요청 본문의 보드 패치가 카드 속성 목록을 건드리는지 본다. 건드리는 경우:

```
잠금이 꺼져 있으면        → 지금까지의 권한 그대로 (변화 없음)
잠금이 켜져 있고 Manage   → 통과
잠금이 켜져 있고 그 미만  → 403
```

"건드린다"는 갱신된 카드 속성이 하나라도 있거나 삭제된 카드 속성이 하나라도 있는
경우다. 속성을 새로 만들든, 이름·유형·필수를 바꾸든, 옵션을 편집하든 모두 이 모양으로
도착한다 — 서버는 다섯 갈래를 구분하지 않는다.

## 응답

| 상황 | 코드 | 비고 |
|---|---|---|
| 통과 | 200 | 기존 응답 형식 그대로 |
| 잠긴 보드에서 Manage 미만 | 403 | 도메인 오류 생성자 사용(헌법 III) |

## 토글 자체의 관문

잠금 설정을 켜거나 끄는 패치는 별도로 Manage를 요구한다(FR-009). 이것은 카드 속성이
아니라 보드 설정 자리를 건드리는 패치이며, 카드 접근 규칙·OKR 보드 토글이 이미 같은
자리에서 같은 방식으로 막힌다.

## 계약 검증 케이스

FR과 1:1로 대응한다. 각 케이스는 P1과 P2 양쪽에서 확인한다.

| ID | 잠금 | 호출자 | 패치 | 기대 |
|---|---|---|---|---|
| C-01 | 꺼짐 | 에디터 | 카드 속성 갱신 | 200 (FR-004) |
| C-02 | 꺼짐 | 에디터 | 카드 속성 삭제 | 200 (FR-004) |
| C-03 | 켜짐 | 에디터 | 카드 속성 갱신 | 403 (FR-005·006·007) |
| C-04 | 켜짐 | 에디터 | 카드 속성 삭제 | 403 (FR-005) |
| C-05 | 켜짐 | 보드 관리자 | 카드 속성 갱신 | 200 (FR-005) |
| C-06 | 켜짐 | 보드 관리자 | 카드 속성 삭제 | 200 (FR-005) |
| C-07 | 켜짐 | 에디터 | 카드 속성을 안 건드리는 패치 | 200 (FR-016) |
| C-08 | 아무 | 에디터 | 잠금 설정 켜기/끄기 | 403 (FR-009) |
| C-09 | 아무 | 보드 관리자 | 잠금 설정 켜기/끄기 | 200 (FR-009) |
| C-10 | 저장값이 boolean이 아님 | 에디터 | 카드 속성 갱신 | 200 (FR-003 — 꺼짐으로 읽는다) |

C-01·C-02·C-07·C-10이 회귀 방지의 핵심이다. 이 기능은 잠그지 않은 보드의 동작을 한 톨도
바꾸지 않아야 한다(US2).
