# Feature Specification: 속성 편집을 관리자에게만 열지 보드가 정한다

**Feature Branch**: `010-admin-only-card-properties`

**Created**: 2026-08-18

**Status**: Draft

**Input**: User description: "보드의 카드 속성 편집(속성 추가·이름 변경·유형 변경·필수 여부 변경·삭제, 그리고 select/multiselect 옵션의 추가·이름 변경·색 변경·순서 변경·삭제)을 시스템관리자와 보드 관리자만 할 수 있게 제한한다. 이 제한은 공유 위젯의 '속성 편집은 관리자만' 토글을 켰을 때만 작동한다."

## 왜 지금이 문제인가

보드가 무엇을 기록하는지는 속성이 정한다. 속성 이름, 유형, 필수 여부, select가 내놓는
옵션 목록 — 이것들은 카드 한 장이 아니라 보드 전체와 이미 쌓인 값에 닿는다. 유형을 바꾸면
기존 값이 읽히지 않고, 옵션을 지우면 그 값을 담은 카드가 한꺼번에 비고, 접근 규칙이
참조하던 옵션이면 규칙까지 깨진다.

지금은 에디터면 누구나 이것을 바꾼다. 카드를 채우라고 준 권한이 보드의 뼈대를 바꾸는
권한까지 함께 준다.

그렇다고 모든 보드를 잠글 수는 없다. 작은 팀이 쓰는 보드에서는 속성을 그때그때 늘리는
것이 정상이고, 잠그면 일이 막힌다. 잠글지 말지는 보드가 정해야 한다.

## 두 가지 편집을 가른다

이 명세에서 "속성 편집"은 **보드가 무엇을 기록하는가**를 바꾸는 일이다.

| 속성 편집 (제한 대상) | 값 편집 (제한 대상 아님) |
|---|---|
| 속성을 새로 만든다 | 카드에 값을 고른다 |
| 속성 이름을 바꾼다 | 카드의 값을 지운다 |
| 속성 유형을 바꾼다 | 이미 있는 select 옵션 중 하나를 고른다 |
| 속성의 필수 여부를 바꾼다 | |
| 속성을 지운다 | |
| select·multiselect의 옵션을 더하거나, 이름·색·순서를 바꾸거나, 지운다 | |

칸반 열은 select 옵션이다. 열을 더하고 이름을 바꾸고 지우는 것은 옵션 편집이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 보드 관리자가 속성 편집을 잠근다 (Priority: P1) 🎯 MVP

보드 관리자가 공유 위젯을 열어 "속성 편집은 관리자만"을 켠다. 그 순간부터 에디터는
속성을 더하거나 이름을 바꾸거나 지울 수 없고, select 옵션도 건드릴 수 없다. 카드에 값을
채우는 일은 그대로 한다.

**Why this priority**: 이 기능의 전부다. 토글과 그 토글이 실제로 막는 동작이 없으면
나머지는 의미가 없다.

**Independent Test**: 보드 관리자로 토글을 켠 뒤 에디터로 로그인해 속성 추가를 시도하면
거절되고, 같은 카드에 값을 고르는 것은 성공한다.

**Acceptance Scenarios**:

1. **Given** 토글이 켜진 보드, **When** 에디터가 속성을 추가하려 하면, **Then** 거절된다
2. **Given** 토글이 켜진 보드, **When** 에디터가 속성 이름·유형·필수 여부를 바꾸려 하면, **Then** 거절된다
3. **Given** 토글이 켜진 보드, **When** 에디터가 속성을 지우려 하면, **Then** 거절된다
4. **Given** 토글이 켜진 보드, **When** 에디터가 select 옵션을 더하거나 이름·색·순서를 바꾸거나 지우려 하면, **Then** 거절된다
5. **Given** 토글이 켜진 보드, **When** 에디터가 카드에 값을 고르거나 지우면, **Then** 성공한다
6. **Given** 토글이 켜진 보드, **When** 보드 관리자가 위 어떤 속성 편집이든 하면, **Then** 성공한다

### User Story 2 - 잠그지 않은 보드는 달라지지 않는다 (Priority: P1)

토글을 켠 적 없는 보드에서는 에디터가 지금까지 하던 대로 속성을 더하고 바꾸고 지운다.
기본값은 꺼짐이고, 이미 있는 모든 보드는 꺼진 상태로 남는다.

**Why this priority**: 회귀가 나면 안 되는 자리다. 이 기능은 기존 보드의 동작을 한 톨도
바꾸지 않아야 한다.

**Independent Test**: 토글을 켠 적 없는 보드에서 에디터로 속성을 추가하면 성공한다.

**Acceptance Scenarios**:

1. **Given** 토글을 켠 적 없는 보드, **When** 에디터가 속성을 추가·변경·삭제하면, **Then** 성공한다
2. **Given** 토글을 켠 적 없는 보드, **When** 에디터가 select 옵션을 편집하면, **Then** 성공한다
3. **Given** 토글을 켰다가 다시 끈 보드, **When** 에디터가 속성을 편집하면, **Then** 성공한다

### User Story 3 - 잠긴 보드에서는 잠긴 조작이 화면에 없다 (Priority: P2)

에디터에게는 속성 추가 버튼, 속성 이름·유형 변경, 속성 삭제, 옵션 편집 항목이 보이지
않는다. 눌러본 뒤 거절당하는 것이 아니라 애초에 없다. 값을 고르는 자리는 그대로 있다.

**Why this priority**: 서버가 막으면 데이터는 지켜진다. 화면은 사용자가 헛수고하지 않게
한다 — 없으면 기능은 동작하되 쓰기 나쁘다.

**Independent Test**: 잠긴 보드를 에디터로 열면 속성 추가 진입점이 화면에 없고, 같은
보드를 보드 관리자로 열면 있다.

**Acceptance Scenarios**:

1. **Given** 잠긴 보드를 보는 에디터, **When** 표 헤더 메뉴를 열면, **Then** 속성 추가·삭제 항목이 없다
2. **Given** 잠긴 보드를 보는 에디터, **When** 카드 상세의 속성 영역을 보면, **Then** 속성 추가 진입점과 속성별 편집 메뉴가 없다
3. **Given** 잠긴 보드를 보는 에디터, **When** select 값을 고르려 열면, **Then** 값 목록은 보이되 옵션을 새로 만들거나 이름·색을 바꾸거나 지우는 조작이 없다
4. **Given** 잠긴 보드를 보는 에디터, **When** 칸반을 보면, **Then** 열 추가와 열 이름·색·삭제 조작이 없다
5. **Given** 잠긴 보드를 보는 보드 관리자, **When** 같은 화면을 보면, **Then** 모든 조작이 있다

### User Story 4 - 스위치는 관리자만 만진다 (Priority: P2)

토글은 보드 관리자에게만 보이고 보드 관리자만 바꾼다. 에디터가 스스로 잠금을 풀 수 있으면
잠금이 아니다.

**Why this priority**: 이게 없으면 US1의 제한이 형식뿐이다. 다만 US1이 먼저 있어야 의미가
생기므로 P2다.

**Independent Test**: 에디터로 공유 위젯을 열면 토글 섹션이 없고, 요청을 직접 보내도
거절된다.

**Acceptance Scenarios**:

1. **Given** 어떤 보드, **When** 에디터가 공유 위젯을 열면, **Then** 토글 섹션이 없다
2. **Given** 어떤 보드, **When** 에디터가 토글을 켜거나 끄는 요청을 보내면, **Then** 거절된다
3. **Given** 어떤 보드, **When** 보드 관리자가 토글을 켜거나 끄면, **Then** 성공하고 결과가 보드에 남는다

### Edge Cases

- 저장된 설정이 참/거짓이 아닌 값(문자열, 숫자, 개체)이면 **꺼짐**으로 읽는다. 보드의 설정
  자리는 다른 기능도 함께 쓰는 자유 형식이라, 반쯤 이해한 값을 "잠김"으로 읽으면 아무도
  잠그지 않은 보드에서 속성 편집이 사라진다.
- 잠긴 보드에서 이미 열려 있던 화면으로 속성 편집을 보내도 서버가 거절한다. 화면이 최신
  설정을 아직 못 받았다는 이유로 통과시키지 않는다.
- 잠금을 켜기 전에 에디터가 만들어 둔 속성과 옵션은 그대로 남는다. 이 기능은 앞으로의
  편집을 막을 뿐 과거를 되돌리지 않는다.
- 보드를 새로 만들거나 복제하는 길은 이 잠금과 무관하다. 만든 사람이 그 보드의 관리자다.
- 잠긴 보드에서 관리자가 옵션을 지우면 그 값을 담은 카드는 지금과 똑같이 값을 잃는다. 이
  기능은 누가 지울 수 있는지만 정하고 지운 결과는 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 보드는 "속성 편집은 관리자만" 상태를 기억한다. 값은 켜짐 또는 꺼짐이다.
- **FR-002**: 그 상태를 한 번도 정한 적 없는 보드는 꺼짐이다. 기존 보드는 전부 꺼짐으로 시작한다.
- **FR-003**: 저장된 값이 켜짐/꺼짐으로 읽히지 않으면 꺼짐으로 취급한다.
- **FR-004**: 토글이 꺼져 있으면 속성 편집 권한은 이 기능이 없던 때와 동일하다.
- **FR-005**: 토글이 켜져 있으면 속성을 추가·삭제하는 일은 보드 관리자 등급에게만 허용한다.
- **FR-006**: 토글이 켜져 있으면 속성의 이름·유형·필수 여부를 바꾸는 일은 보드 관리자 등급에게만 허용한다.
- **FR-007**: 토글이 켜져 있으면 select·multiselect 옵션을 추가·이름 변경·색 변경·순서 변경·삭제하는 일은 보드 관리자 등급에게만 허용한다.
- **FR-008**: 토글 상태와 무관하게, 카드가 담는 값을 고르고 바꾸고 지우는 일은 기존 권한 그대로 둔다.
- **FR-009**: 토글 자체를 켜고 끄는 일은 보드 관리자 등급에게만 허용한다.
- **FR-010**: 서버가 위 제한을 강제한다. 화면을 거치지 않은 요청도 같은 답을 받는다.
- **FR-011**: 카드 속성을 바꾸는 모든 요청 경로에서 같은 판정을 한다. 한 경로만 막으면 다른 경로로 같은 편집이 통과한다.
- **FR-012**: 잠긴 보드에서 에디터에게는 잠긴 조작의 진입점을 보여주지 않는다. 대상 화면은 표 헤더 메뉴, 카드 상세 속성 영역, select·multiselect 값 입력, 칸반 열 머리와 열 추가다.
- **FR-013**: 잠긴 보드에서도 에디터에게 값을 고르고 지우는 자리는 그대로 보여준다.
- **FR-014**: 토글은 보드 관리자에게만 보인다.
- **FR-015**: 보드 생성·복제 경로는 이 기능이 바꾸지 않는다.
- **FR-016**: 뷰 관리, 보드 제목·설명처럼 카드 속성 스키마가 아닌 것은 이 기능이 바꾸지 않는다.

### Key Entities

- **속성 편집 잠금**: 보드가 기억하는 켜짐/꺼짐 하나. 접근 규칙·OKR 보드 설정·조직 색과
  같은 자리에 산다. 정해진 적 없으면 꺼짐이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 잠긴 보드에서 에디터가 시도하는 속성 편집은 종류를 불문하고 100% 거절된다 — 추가, 이름·유형·필수 변경, 삭제, 옵션 편집 다섯 갈래 전부.
- **SC-002**: 잠긴 보드에서 에디터가 카드 값을 고르고 지우는 일은 100% 성공한다.
- **SC-003**: 잠그지 않은 보드에서 에디터가 하는 속성 편집은 이 기능 도입 전과 결과가 동일하다.
- **SC-004**: 잠긴 보드를 에디터가 볼 때, 잠긴 조작의 진입점이 화면에 하나도 남지 않는다.
- **SC-005**: 에디터는 토글을 켜거나 끌 수 없다 — 화면으로도, 요청을 직접 보내서도.
- **SC-006**: 보드 관리자는 잠금 여부와 무관하게 모든 속성 편집을 할 수 있다.

## Assumptions

- "보드 관리자 등급"은 이 저장소가 카드 접근 규칙과 OKR 보드 토글에 이미 쓰는 것과 같은
  바를 뜻한다. 보드 관리자, 그리고 보드 멤버인 팀관리자·시스템관리자가 통과한다. 보드
  멤버가 아닌 시스템관리자는 지금도 보드를 수정할 수 없으므로 이 기능이 그 자리를 새로
  열지 않는다.
- 잠금은 보드 단위다. 속성 하나만 골라 잠그는 길은 이번 범위가 아니다.
- 토글의 기본값이 꺼짐이므로 마이그레이션이 필요 없다. 기존 보드는 값이 없는 상태로 남고
  그것이 곧 꺼짐이다.
- 잠금 상태 변경은 보드의 다른 설정 변경과 같은 방식으로 기록되고 다른 참여자에게 전달된다.

## 범위 밖

- 속성별 잠금(어떤 속성은 잠그고 어떤 속성은 열어두기)
- 잠금을 켜기 전에 만들어진 속성·옵션의 정리나 회수
- 잠금 상태 변경 이력을 따로 보여주는 화면
- 뷰·보드 제목·설명·멤버십 등 카드 속성 스키마가 아닌 편집의 권한 변경
- 보드 생성·복제·가져오기 경로의 권한 변경
