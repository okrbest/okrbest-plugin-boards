# Quickstart: 숨긴 보드를 사이드바에서 되찾는다

**Spec**: [spec.md](./spec.md) | **Contracts**: [ui-surfaces](./contracts/ui-surfaces.md), [unhide-flow](./contracts/unhide-flow.md)

헌법 원칙 I은 화면 동작이 바뀌는 변경에 게이트만으로 부족하다고 못 박는다. 빌드·배포 뒤
실제 계정으로 아래를 훑고 그 결과를 완료 근거로 제시한다.

## 사전 준비

```bash
# webapp만 바뀌었으므로 Go 빌드는 건너뛴다 (약 40초)
make webapp && make deploy-from-watch
```

배포 뒤 브라우저 **하드 리프레시**가 필요하다. 번들 경로에 콘텐츠 해시가 박혀 있다.
서빙 번들이 새것인지는 `/api/v4/plugins/webapp`의 `bundle_path`를
`/static/plugins/focalboard/` 아래로 요청해 새 문자열(예: `HiddenBoards`)을 grep 하면 안다.

계정은 하나면 된다. 숨김은 개인 설정이라 관리자·비관리자 구분이 없다. 다만 **카테고리에
실제로 속한 보드**로 확인한다 (R11). 비관리자 계정은 화면에서만 복구된 보드가 많으니,
먼저 사이드바에서 보드 순서를 한 번 바꿔 서버 카테고리에 등록시킨 뒤 시작한다.

준비물: 보드가 3개 이상 든 카테고리 하나. 없으면 사용자 지정 카테고리를 만들어 보드
3개를 끌어다 놓는다.

## 시나리오 1 — 숨기고 바로 되돌린다 (US2)

1. 보드 A의 `⋯` 메뉴 → `보드 숨기기`
2. 화면 아래에 `'A' 보드를 숨겼습니다`와 `실행 취소`가 뜬다 → U-07
3. 5초 안에 `실행 취소`를 누른다
4. A가 카테고리의 **원래 자리**에 돌아오고 알림이 사라진다 → U-08, SC-004
5. 다시 A를 숨기고 이번엔 기다린다. 알림이 사라지고 A는 숨김 상태다 → U-07

## 시나리오 2 — 접힘 행에서 되찾는다 (US1)

1. 보드 B도 숨긴다. 카테고리 아래에 `숨긴 보드 2개` 행이 흐리게 보인다 → U-01
2. 행을 누른다. A·B가 흐린 글씨와 눈 꺼짐 아이콘으로 펼쳐진다 → U-02, U-03
3. A 위에 마우스를 올리면 `다시 표시`가 나타난다. 누른다 → U-04
4. A가 원래 자리로 돌아오고 행은 `숨긴 보드 1개`로 준다
5. 행을 접었다 펼친다. 상태가 따라온다. 페이지를 새로 열면 접혀 있다 → FR-003

## 시나리오 3 — 전부 숨긴 카테고리 (US3)

1. 남은 보드를 모두 숨긴다
2. 카테고리를 펼쳐 본다. `해당 카테고리에 보드가 존재하지 않음`은 **없고** `숨긴 보드 N개`
   행만 있다 → U-06
3. (대조) 보드가 하나도 없는 카테고리를 만들어 펼친다. 끌어다 놓기 안내가 지금처럼 보인다

## 시나리오 4 — 모두 표시 (US4)

1. 시나리오 3 상태에서 행을 펼치고 `모두 표시`를 누른다 → U-05
2. 모든 보드가 원래 순서로 돌아오고 행이 사라진다

## 시나리오 5 — 다른 탭에 반영 (FR-014)

1. 같은 계정으로 탭 두 개를 연다
2. 탭 1에서 보드 하나를 숨기고, 탭 2의 행 수가 늘어나는지 본다
3. 탭 2에서 `다시 표시`, 탭 1에서 보드가 돌아오는지 본다

## 시나리오 6 — 실패가 조용히 사라지지 않는다 (SC-006)

1. DevTools Network에서 `/unhide` 요청을 차단(Block request URL)한다
2. `다시 표시`를 누른다
3. `보드를 다시 표시하지 못했습니다` 알림이 뜨고 항목은 행에 그대로 남는다 → U-09
4. 차단을 풀고 다시 누르면 돌아온다

## 시나리오 7 — 끌어 놓기가 그대로다 (SC-005)

1. 숨긴 보드가 2개 있는 상태에서 보이는 보드를 위아래로 끌어 옮긴다
2. 옮긴 자리가 정확하고 오류 화면이 뜨지 않는다. 새로 열어도 순서가 유지된다 → U-10
