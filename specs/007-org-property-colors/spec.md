# Feature Specification: 조직 속성 값에 색을 입힌다

**Feature Branch**: `007-org-property-colors`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "본부, 부서, 직책, 담당자처럼 데이터를 불러온 속성 유형도 랜덤하게 배경색 설정할 수 있는지 확인해줘 → B 방식으로 진행(사용자, 다중 사용자는 배경색 적용 필요 없음)"

005·006으로 본부·부서·직책이 카드의 1급 속성이 됐다. 그런데 **값이 전부 같은 회색이다.**
카드에 본부장과 팀장이 나란히 붙어 있어도 두 라벨이 똑같이 생겼다. 선택 속성은
옵션마다 색을 골라 한눈에 구분하는데, 조직 속성만 그 수단이 없다.

막힌 이유는 의도의 부작용이다. 조직 마스터는 메인 서버 소유라 이 플러그인이 이름을
바꾸거나 지울 수 없고, 그 사실을 드러내려고 값 편집기에서 옵션 메뉴를 통째로 뺐다.
이름 변경·삭제와 **색 변경이 한 덩어리로 묶여 있어서** 색까지 같이 사라졌다.

이 기능은 둘을 떼어낸다. 조직은 여전히 못 고치고, 색은 고칠 수 있게 한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 색을 고르지 않아도 구분된다 (Priority: P1)

기획자가 카드에 본부장과 팀장을 적는다. 아무 설정도 하지 않았는데 두 라벨의 색이
다르다. 표를 훑을 때 글자를 읽지 않고도 어느 카드가 어느 직책인지 눈에 들어온다.

**Why this priority**: 이 기능의 값어치 대부분이 여기서 나온다. 조직 단위가 수십 개인
보드에서 하나씩 색을 고르라고 하면 아무도 안 한다. 손대지 않아도 구분되는 것이
기본값이어야 한다.

**Independent Test**: 색을 한 번도 지정하지 않은 보드에서 조직 값이 여러 개인 카드를
열어, 값마다 배경색이 다른지 확인한다.

**Acceptance Scenarios**:

1. **Given** 색을 지정한 적 없는 보드, **When** 카드에 조직 값 여러 개를 적으면, **Then** 값마다 서로 다른 배경색으로 보인다
2. **Given** 같은 본부를 적은 카드 두 장, **When** 둘을 나란히 보면, **Then** 같은 색이다
3. **Given** 같은 본부를 쓰는 다른 보드, **When** 그 보드를 열면, **Then** 색을 지정한 적 없는 한 같은 색이다
4. **Given** 브라우저를 새로 고침, **When** 같은 카드를 다시 보면, **Then** 색이 그대로다

---

### User Story 2 - 색을 직접 고른다 (Priority: P2)

팀장이 자기 본부를 눈에 띄는 색으로 바꾼다. 자동으로 배정된 색이 옆 부서와 헷갈려서다.

**Why this priority**: 자동 배정으로 대부분 해결되지만, 보고용 보드에서는 "우리 본부는
파란색"처럼 의미를 싣고 싶어진다. US1 없이는 성립하지 않으므로 두 번째다.

**Independent Test**: 조직 값의 색을 바꾸고, 그 값이 나오는 자리마다 새 색으로 보이는지
확인한다. 다른 값의 색은 그대로여야 한다.

**Acceptance Scenarios**:

1. **Given** 조직 값 편집기, **When** 값의 색 메뉴를 열면, **Then** 기존 팔레트가 나온다
2. **Given** 색을 고르면, **Then** 그 값이 나오는 모든 자리가 새 색으로 바뀐다
3. **Given** 색을 고른 값, **When** 지정을 해제하면, **Then** 자동 배정 색으로 돌아간다
4. **Given** 색 메뉴, **When** 메뉴를 살펴보면, **Then** 이름 변경·삭제는 여전히 없다
5. **Given** 한 보드에서 색을 바꿔도, **When** 같은 조직을 쓰는 다른 보드를 열면, **Then** 그 보드의 색은 바뀌지 않는다

---

### User Story 3 - 거를 때도 묶을 때도 같은 색이다 (Priority: P3)

본부장이 직책으로 보드를 묶어 본다. 그룹 제목의 색이 카드 라벨의 색과 같아서 어느
그룹이 무엇인지 바로 안다.

**Why this priority**: 색이 자리마다 다르면 없느니만 못하다. 다만 값을 적고 색을 고르는
일이 먼저 되어야 확인할 수 있다.

**Independent Test**: 색을 지정한 조직 값으로 필터 목록과 그룹 제목을 열어, 카드에서
본 색과 같은지 대조한다.

**Acceptance Scenarios**:

1. **Given** 필터 패널의 조직 속성, **When** 값 목록을 보면, **Then** 카드에서 본 색과 같다
2. **Given** 조직 속성으로 묶은 보기, **When** 그룹 제목을 보면, **Then** 카드에서 본 색과 같다
3. **Given** 값이 여러 개인 그룹, **When** 제목을 보면, **Then** 여러 값이 묶였다는 것이 드러난다

---

### Edge Cases

- **조직 마스터에서 사라진 값은?** 경고 표시가 색보다 우선한다. 자동 배정 색도 지정
  색도 덮어쓰지 않는다 — 값이 사라졌다는 신호가 예쁜 색보다 중요하다.
- **색을 지정한 뒤 그 조직이 삭제되면?** 지정은 남지만 화면에는 경고 표시가 나온다.
  조직이 되살아나면 지정한 색이 다시 보인다.
- **조직 단위가 팔레트보다 많으면?** 색이 겹친다. 색은 훑기를 돕는 보조 수단이고 값을
  최종적으로 구분하는 것은 이름이다.
- **한 보드에 같은 조직 속성이 두 개면?** 같은 조직 단위는 두 속성에서 같은 색이다.
  색은 속성이 아니라 조직 단위에 붙는다.
- **보드를 복제하면?** 지정한 색도 함께 복제된다.
- **색을 한 번도 안 건드린 보드는?** 저장되는 것이 없다. 자동 배정은 계산으로 나온다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 색을 지정하지 않은 조직 값은 조직 단위마다 자동으로 배정된 배경색으로 보인다.
- **FR-002**: 자동 배정은 같은 조직 단위에 항상 같은 색을 준다 — 새로 고쳐도, 다른 보드에서도, 다른 사용자가 봐도 같다.
- **FR-003**: 사용자는 조직 값의 배경색을 팔레트에서 고를 수 있다.
- **FR-004**: 지정한 색은 자동 배정을 덮어쓴다.
- **FR-005**: 지정을 해제하면 자동 배정 색으로 돌아간다.
- **FR-006**: 지정한 색은 보드 단위로 남는다. 다른 보드의 같은 조직 단위에는 영향이 없다.
- **FR-007**: 조직 값이 보이는 세 자리 — 카드 편집기, 필터 목록, 그룹 제목 — 에 같은 색이 나온다.
- **FR-008**: 색은 기존 팔레트에서만 고른다. 새 색을 만들지 않는다.
- **FR-009**: 조직 마스터에서 사라진 값은 색 지정 여부와 무관하게 경고 표시를 유지한다.
- **FR-010**: 색을 다루는 자리에서 조직 이름 변경·삭제·추가는 여전히 불가능하다.
- **FR-011**: 색을 저장해도 카드 접근 규칙이 고를 수 있는 속성 목록은 달라지지 않는다.
- **FR-012**: 담당자·다중 사용자 속성의 화면은 바뀌지 않는다.

### Key Entities

- **조직 단위**: 본부·부서·직책. 메인 서버가 소유하고 이 플러그인은 읽기만 한다. 색은
  조직 단위에 붙지만 **조직 마스터에 저장되지 않는다.**
- **보드의 색 지정**: 보드 하나가 기억하는 "조직 단위 → 색" 목록. 사용자가 고른 것만
  들어간다. 비어 있는 것이 정상이며, 그때는 전부 자동 배정으로 보인다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 색을 한 번도 지정하지 않은 보드에서, 서로 다른 조직 단위 8개가 서로 다른 색으로 보인다.
- **SC-002**: 같은 조직 단위의 자동 색이 새로고침·다른 보드·다른 계정에서 100% 같다.
- **SC-003**: 색을 바꾸면 그 값이 나오는 세 자리 전부가 바뀐다 — 누락 0건.
- **SC-004**: 색을 지정하기 전과 후에 접근 규칙이 고를 수 있는 속성 목록이 동일하다 (변화 0건).
- **SC-005**: 담당자·다중 사용자 화면에 시각적 변화 0건.
- **SC-006**: 005·006 시나리오 회귀 0건.

## 범위 밖

- **담당자·다중 사용자 색** — 아바타가 이미 값을 구별해 준다. 색을 더하면 시끄러워진다.
- **팀 전체 공통 색** — 팀 단위 저장소와 API가 새로 필요해 서버까지 번진다. 보드마다
  지정하는 것으로 시작한다.
- **조직 마스터에 색 저장** — 메인 서버 소유다.
- **새 색 팔레트** — 기존 것을 쓴다.
- **선택·다중 선택 속성의 색 동작 변경** — 지금 그대로다.

## Assumptions

- 자동 배정은 팔레트에서 **기본 회색을 뺀** 색들 중에서 고른다. 회색이 섞이면 "색이
  없는 값"과 구별되지 않는다.
- 색을 바꾸는 권한은 보드 속성을 바꿀 수 있는 사람과 같다. 색은 보드에 저장되므로
  보드를 편집할 수 있으면 색도 바꿀 수 있다.
- 색 지정 UI는 선택 속성이 색을 고르는 자리와 같은 모양을 쓴다. 사용자가 새로 배울
  것이 없어야 한다.
- 조직 단위 수가 팔레트 크기를 넘으면 색이 겹치는 것을 받아들인다.
- 005·006이 정한 조직 속성의 나머지 동작(저장 형식, 좁히기, 사라진 값 처리)은 그대로다.
