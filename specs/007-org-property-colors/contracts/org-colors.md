# 계약: 조직 값의 색

**Feature**: `007-org-property-colors`

색이 기존 속성 체계·위젯과 맺는 계약이다. 저장 형식과 결정 규칙은
[data-model.md](../data-model.md)에 있고, 여기서는 **주변 코드가 색을 어떻게 얻고
바꾸는가**를 정한다.

005·006의 계약([본부·부서](../../005-org-scoped-properties/contracts/property-types.md),
[직책](../../006-org-duty-property/contracts/property-types.md))을 확장한다. 그 문서들이
정한 것 중 여기서 다시 말하지 않는 것은 그대로 유효하다.

---

## 1. 색을 얻는 곳은 하나다

조직 값의 색을 정하는 함수는 `properties/orgLabels.ts`에 산다. 006이 이름 해석을
모아 둔 파일이고, 색의 소비자도 같은 셋이다.

```
색 결정 = f(조직 단위 ID, 마스터 목록, 보드의 색 지정)
```

세 소비자 — 카드 편집기, 필터 목록, 그룹 헤더 — 는 **직접 색을 계산하지 않는다.**
해시를 다시 구현하거나 우선순위를 다시 쓰는 코드가 생기면 세 자리가 갈라진다.

---

## 2. 팔레트

`Constants.menuColors`를 그대로 쓴다. 새 색을 만들지 않는다.

| 쓰임 | 범위 |
|---|---|
| 자동 배정 | `propColorDefault`를 뺀 9종 |
| 사용자 선택 | 10종 전부 (회색도 고를 수 있다) |
| 사라진 값 | `propColorRed` 고정 |

---

## 3. 저장

`board.properties.orgColors`에 `{조직 단위 ID: 팔레트 키}`로 저장한다.

**`cardProperties[].options`에 넣지 않는다.** 조직 속성의 옵션 배열이 비어 있다는
사실이 접근 규칙에서 조직 속성을 빼는 장치이기 때문이다(`propertyAccessRow.tsx`는
옵션이 있는 속성만 규칙 후보로 올린다). 색을 옵션에 넣으면 006 FR-011이 깨진다.

읽고 쓰는 방식은 접근 규칙과 같다.

| | 방법 |
|---|---|
| 읽기 | `board.properties?.orgColors`, 팔레트에 없는 값은 무시 |
| 쓰기 | 보드를 복제해 키를 갈아 끼우고 `mutator.updateBoard` |
| 실행 취소 | `updateBoard`가 이미 제공한다 — 따로 만들지 않는다 |
| 권한 | 보드를 편집할 수 있으면 색도 바꿀 수 있다 |

---

## 4. 값 편집기의 메뉴

`ValueSelector`의 `fixedOptions`는 지금 옵션 메뉴를 통째로 없앤다. 이를 **색만 있는
메뉴**로 쪼갠다.

| `fixedOptions` | `onChangeColor` | 메뉴 |
|---|---|---|
| `false` | 있음 | 이름 변경·삭제·색 (지금 그대로) |
| `true` | 없음 | 메뉴 없음 (지금 그대로) |
| `true` | **있음** | **색만** ← 이번에 생기는 조합 |

이름 변경·삭제·추가는 조직 속성에서 **여전히 불가능하다.** 마스터는 메인 서버 소유다.
색은 보드의 표시 설정이지 조직 데이터가 아니므로 다르게 다룬다.

메뉴에 색 지정을 해제하는 항목을 하나 둔다. 해제하면 저장에서 그 조직 단위의 키를
지우고 자동 색으로 돌아간다 — 회색으로 만드는 것이 아니다.

---

## 5. 세 자리의 표시

| 자리 | 위젯 | 이번 변경 |
|---|---|---|
| 카드 편집기 | `Label` | 고정 회색 → 결정된 색 |
| 필터 목록 | `<span>` → **`Label`** | 위젯을 바꾼다. 새 SCSS 파일을 만들지 않고 기존 패널 스타일 안에서 맞춘다 |
| 그룹 헤더 | `Label` (색이 빈 문자열) | `centerPanel`이 이름을 덮어쓰는 자리에서 색도 채운다 |

그룹에 값이 여럿이면 **첫 값의 색**을 쓴다. 선택 속성의 그룹이 이미 그렇다.

`boardUtils.ts`는 건드리지 않는다. 모든 속성 유형이 지나는 공용 경로라 조직 전용
조회를 넣으면 안 된다.

---

## 6. 건드리지 않는 것

| 대상 | 이유 |
|---|---|
| 담당자·다중 사용자 | `Label`을 거치지 않고 react-select 칩과 아바타로 그린다. 아바타가 이미 값을 구별한다 |
| 선택·다중 선택 | 색 동작이 이미 있다. 그대로 둔다 |
| 접근 규칙 | 건드리지 않는 것이 FR-011을 지키는 방법이다 |
| 조직 마스터 | 메인 서버 소유. 색은 플러그인 쪽에만 산다 |
| 서버 | 저장은 기존 보드 patch 경로를 탄다 |

---

## 7. i18n

새 문자열은 색 지정 해제 항목 하나뿐이다. 색 이름은 `Constants.menuColors`가 이미
가지고 있다.

원칙 V에 따라 `en.json`과 `ko.json`을 같은 변경에서 갱신한다.

---

## 8. 하위 호환

`orgColors`를 모르는 구버전 클라이언트는 키를 무시하고 조직 값을 예전처럼 회색으로
그린다. 값 자체는 건드려지지 않으므로 신버전에서 다시 열면 색이 보인다. 006이 배포될
때와 같은 상황이다.
