# 데이터 모델: 조직 속성 값에 색을 입힌다

**Feature**: `007-org-property-colors`

새 테이블도, 새 마이그레이션도, 새 엔드포인트도 없다. 이 문서는 **색이 어디서 오고
무엇이 저장되는가**를 적는다.

---

## 1. 저장되는 것 — 지정한 색만

기존 보드 JSON에 키 하나가 붙는다.

```jsonc
// focalboard_boards.properties
{
  "propertyAccess": { /* 006까지의 접근 규칙 */ },
  "orgColors": {
    "o9hrktz6tbgn3c74hsyzoc57nh": "propColorBlue",
    "ndrn1qq69b8btpgohrez3m1khy": "propColorGreen"
  }
}
```

| 규칙 | 값 |
|---|---|
| 키 | 조직 단위 ID (본부·부서·직책 구분 없음) |
| 값 | 팔레트 키 (`Constants.menuColors`의 키) |
| 범위 | 보드 하나 |
| 없을 때 | 키 자체가 없다. 빈 객체를 만들어 두지 않는다 |
| 검증 | 서버는 하지 않는다. 읽을 때 팔레트에 있는 키인지 확인한다 |

**속성 ID가 키에 없는 것이 의도다.** 색은 조직 단위에 붙지 속성에 붙지 않는다. 한
보드에 본부 속성이 둘이면 같은 본부는 둘 다 같은 색이다.

**저장하지 않는 것**: 자동 배정 색. 계산이라 저장할 것이 없다.

---

## 2. 색 결정 규칙

한 값의 색은 세 갈래로 정해진다. 위에서부터 이긴다.

| 순위 | 조건 | 색 |
|---|---|---|
| 1 | 조직 마스터에 없는 ID | 경고색 (`propColorRed`) |
| 2 | 보드의 `orgColors`에 있음 | 그 색 |
| 3 | 그 외 | `팔레트[hash(ID) % 9]` |

**경고색이 지정 색을 이긴다.** 색을 지정한 뒤 그 조직이 삭제되면, 예쁜 색보다 "이 값이
사라졌다"는 신호가 중요하다. 조직이 되살아나면 지정한 색이 다시 보인다 — 지정은 지워지지
않는다.

**팔레트에서 회색을 뺀다.** 자동 배정은 `propColorDefault`를 제외한 9종에서 고른다.
회색이 섞이면 자동 배정된 값과 색이 없는 값을 구별할 수 없다. 사용자가 회색을 직접
고르는 것은 막지 않는다 — 그건 의도한 선택이다.

**저장된 색이 팔레트에 없으면** 3순위로 떨어뜨린다. 자유 형식 JSON이라 손으로 편집되거나
구버전이 남긴 값이 올 수 있고, 화면이 깨지는 것보다 자동 색으로 도는 편이 낫다.

---

## 3. 해시

같은 ID는 언제나 같은 색이어야 한다. 배포·플랫폼·브라우저에 의존하면 안 된다.

- 문자열 해시(djb2 계열)를 직접 구현한다. 자바스크립트 내장 해시는 없고, 라이브러리를
  들일 만한 무게가 아니다.
- 결과는 음수가 나올 수 있으므로 절댓값을 취한 뒤 나머지를 구한다.
- **색이 겹치는 것을 받아들인다.** 조직 단위가 9개를 넘으면 겹친다. 색은 훑기를 돕는
  보조 수단이고 값을 최종 구분하는 것은 이름이다.

---

## 4. 소비자 셋

세 자리가 같은 결정 규칙을 쓴다. 하나라도 다르면 FR-007 위반이다.

| 자리 | 지금 | 이후 |
|---|---|---|
| 카드 편집기 | 고정 회색 | 결정 규칙 |
| 필터 목록 | 색 없음 (텍스트) | 결정 규칙 |
| 그룹 헤더 | 색 없음 (빈 문자열) | 결정 규칙 |

그룹 헤더는 값이 여럿일 수 있다. **첫 값의 색을 쓴다** — 선택 속성의 그룹이 이미
그렇게 한다.

---

## 5. 하위 호환

- **기존 보드**: `orgColors` 키가 없다. 전부 자동 색으로 보인다. 저장은 사용자가 색을
  처음 고를 때 생긴다.
- **보드 복제**: `properties`가 통째로 복제되므로 색 지정도 따라간다.
- **구버전 클라이언트**: `orgColors`를 모르므로 무시한다. 조직 값은 예전처럼 회색으로
  보이고, 값 자체는 건드려지지 않는다.
- **006 이전 보드**: 조직 속성이 없으므로 해당 없음.
