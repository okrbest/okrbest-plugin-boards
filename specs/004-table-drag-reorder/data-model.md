# Phase 1 Data Model: 표 보기 드래그 재정렬·중첩

**Date**: 2026-08-05 | **Plan**: [plan.md](plan.md)

**저장 스키마 변경은 없다.** 서버 모델도 API도 그대로다. 아래는 드래그가 사는 동안만 존재하는 화면 쪽 모델과, 드롭이 기존 저장 데이터를 어떻게 건드리는지다.

## 기존 저장 데이터 (변경 없음)

| 개념 | 어디에 사는가 | 이번 기능에서의 역할 |
|---|---|---|
| 카드의 부모 | 카드 블록의 `fields.parentCardId` (빈 문자열 = 최상위) | 계층 이동의 대상. `link`/`unlink` API가 쓴다 |
| 카드의 깊이 | 카드 블록의 `fields.depth` (0 = 최상위, 최대 5) | 인디케이터 들여쓰기와 깊이 클램프의 입력. 자손 값은 서버가 재귀 갱신한다 |
| 카드 순서 | 보기 블록의 `fields.cardOrder` (카드 id 배열) | 순서 이동의 대상. 서브트리는 여기서 연속 구간이 된다 |
| 그룹 속성값 | 카드 블록의 `fields.properties[groupById]` | 다른 그룹의 하위로 들어갈 때 새 부모 값으로 맞춘다 |

## 화면 모델 (드래그 중에만 존재)

### DragItem — 무엇을 끌고 있는가

`useDrag`의 `item`으로 실린다. 드래그 시작 시 한 번 만들어지고 끝까지 바뀌지 않는다.

| 필드 | 뜻 | 만드는 법 |
|---|---|---|
| `cardId` | 끄는 카드 | 행이 가진 값 |
| `subtreeIds` | 함께 움직일 카드 전체. **부모가 맨 앞, 이어서 깊이우선 자손** | 하위 카드 맵을 재귀로 훑는다 (research R7) |
| `subtreeHeight` | 끄는 카드 아래로 몇 단이 더 있는가 (자손 없으면 0) | 같은 재귀에서 함께 구한다 |
| `sourceParentId` | 끌기 전의 부모 (`''` = 최상위) | 되돌리기와 "부모가 안 바뀌면 link/unlink 생략" 판정에 쓴다 |
| `sourceDepth` | 끌기 전의 깊이 | 깊이 변화 계산 |
| `selectedCardIds` | 함께 선택돼 있던 카드들 (없으면 빈 배열) | **기존 다중 선택 순서 이동을 유지하기 위한 것** (FR-031) |

**다중 선택 (FR-031).** 지금 `onDropToGroup`은 `selectedCardIds ∪ {srcCard.id}`를 한 덩어리로 옮긴다(`table.tsx:138`). 드롭 핸들러를 갈아끼우면서 이 동작을 잃지 않도록 `DragItem`에 담아 넘긴다.

`subtreeIds`와의 관계를 정한다.

- **순서 이동**(`intent.parentCardId === sourceParentId`)이면 이동 대상은 `selectedCardIds ∪ {cardId}`의 각 서브트리를 합친 것이다.
- **계층 이동**(부모가 바뀜)이면 대상은 끄는 카드의 서브트리 **하나뿐**이다. 여러 카드를 한 번에 하위로 넣는 것은 명세 범위 밖이다(spec Assumptions). 다중 선택 상태에서 계층 이동을 하면 나머지 선택은 무시한다.

`subtreeIds`의 순서가 곧 `cardOrder`에 끼워 넣을 순서다. 이 한 가지가 FR-017(자손이 상대적 계층 유지)을 보장한다.

### RowMetric — 화면에 그려진 행 하나

컨텍스트가 행마다 등록받는다. **접힌 그룹의 행은 등록하지 않는다** (research R3).

| 필드 | 뜻 |
|---|---|
| `cardId` | 이 행의 카드 |
| `depth` | 이 행의 현재 깊이 |
| `parentCardId` | 이 행의 현재 부모 |
| `top` | `.Table` 콘텐츠 좌표계의 상단 y |
| `height` | 행 높이 |
| `groupValue` | 이 행이 속한 그룹의 값 (그룹 미사용 시 `undefined`) |

등록 순서 = 화면에 보이는 순서다. 판정 모듈은 이 배열의 인접 관계로 깊이 범위를 정한다.

### DropIntent — 지금 놓으면 어떻게 되는가

판정 모듈의 출력. **놓을 수 없으면 `null`이다** — 이 한 가지 표현이 FR-008(놓을 수 없으면 선을 그리지 않음)과 FR-013(자기 자손 금지)을 한 자리에 모은다.

| 필드 | 뜻 |
|---|---|
| `boundaryIndex` | 몇 번째 행 앞의 경계인가 (0 = 첫 행 위, N = 마지막 행 아래) |
| `depth` | 클램프를 마친 목표 깊이 |
| `parentCardId` | 그 깊이에서의 새 부모 (`''` = 최상위) |
| `anchorTop` | 선을 그릴 y (`.Table` 콘텐츠 좌표) |
| `indentOffsetPx` | 선의 시작 x = `depth × indentStepPx` |

`indentOffsetPx`(출력, 선의 시작 x)와 판정 입력 `indentStepPx`(깊이 한 단계의 px = 22)는 다른 값이다. 이름을 갈라 둔 이유는 [contracts/drop-target.md](contracts/drop-target.md)에 있다.

`parentCardId`는 `depth`에서 파생되지만 미리 계산해 담는다. 적용 단계가 다시 행 배열을 훑지 않아도 되고, 테스트에서 "이 좌표면 누구의 자식이 되는가"를 직접 단언할 수 있다.

## 상태 전이

```
       ┌──────────┐
       │  idle    │
       └────┬─────┘
            │ 핸들 mousedown
            ▼
       ┌──────────┐   커서 이동(rAF마다)   ┌────────────────┐
       │ dragging ├───────────────────────►│ intent = 계산값 │
       │          │◄───────────────────────┤ 또는 null       │
       └────┬─────┘                        └────────────────┘
            │
            ├─ drop, intent = null ──────► 아무 일 없음 → idle
            │
            ├─ drop, intent ≠ null, 정렬 켜짐 ──► 확인 대화
            │        ├─ 거부 ────────────────► 아무 일 없음 → idle
            │        └─ 승인 ──► 정렬 해제 ──┐
            │                                 │
            └─ drop, intent ≠ null, 정렬 꺼짐 ┴─► 적용 → idle
            │
            └─ ESC / 취소 ──────────────────► 아무 일 없음 → idle
```

`intent`는 드래그가 끝나면 반드시 버려진다. 드래그 밖에서 이 값이 남아 있으면 안 된다.

## 적용 단계가 데이터를 바꾸는 순서

하나의 되돌리기 그룹 안에서 순서대로 실행한다 (research R1).

| # | 조건 | 하는 일 | 건드리는 것 |
|---|---|---|---|
| 1 | `intent.parentCardId ≠ item.sourceParentId` | 새 부모가 있으면 `link`, 없으면 `unlink` | 끄는 카드의 `parentCardId`·`depth`. **자손 `depth`는 서버가 재귀 갱신** |
| 2 | 그룹이 걸려 있고 새 부모의 그룹 값이 다르면 | 끄는 카드의 그룹 속성값을 새 부모 값으로 | 끄는 카드의 `properties[groupById]`. **자손은 건드리지 않는다** (FR-023) |
| 3 | 항상 | `subtreeIds`를 통째로 빼서 목표 경계에 끼워 넣는다 | 보기의 `cardOrder` |

3번의 시드는 **보드 전체 카드**로 채운다. 지금은 최상위 카드만 담아 하위 카드 id가 빠진다(design.md B1).

## 불변식

구현이 지켜야 하고, 테스트가 확인해야 하는 것들.

1. `cardOrder` 안에서 어떤 카드의 자손은 그 카드 바로 뒤에 연속으로 놓인다.
2. 어떤 카드의 `depth`는 항상 부모의 `depth` + 1이다. 최상위는 0이다.
3. 어떤 카드도 자기 자손을 조상으로 갖지 않는다.
4. 모든 카드의 `depth`는 5 이하다.
5. 하위 카드의 화면 순서는 `cardOrder`의 순서와 같다. (지금 깨져 있다 — B3)

1·5는 화면이 지킨다. 2·3·4는 서버가 최종 판정자이고, 화면은 어길 수 있는 조작을 애초에 제공하지 않는 방식으로 협력한다.
