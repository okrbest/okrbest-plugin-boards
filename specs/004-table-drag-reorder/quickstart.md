# Quickstart: 표 보기 드래그 재정렬·중첩 검증

**Date**: 2026-08-05 | **Plan**: [plan.md](plan.md)

기능이 실제로 동작하는지 확인하는 절차. 자동 게이트와 수동 확인으로 나뉜다.

**수동 확인이 형식적 절차가 아니다.** 실제 HTML5 드래그 이벤트를 자동으로 흘릴 수 없어(`react-dnd-test-backend` 미설치, 기존 표·칸반 테스트도 드래그를 시뮬레이션하지 않음) 판정 규칙과 배선만 자동으로 덮인다. **둘을 잇는 부분은 여기서만 검증된다.**

## 전제

- 로컬 Mattermost가 `http://localhost:8065`에서 돌고 있다
- 플러그인이 배포돼 있다 — **소스만 고치면 반영되지 않는다**
- 하위 카드가 있는 표 보기 보드가 하나 있다

## 자동 게이트

```bash
make webapp-ci      # npm run check + npm run test + npm run check-types
```

서버는 건드리지 않으므로 `server-lint`·`server-test`는 이번 변경의 게이트가 아니다.

**회귀 판정은 실패 개수가 아니라 실패 스위트 목록의 diff로 한다.** 이 저장소는 깨끗한 상태에서도 실패하는 테스트가 있다. 변경 전후로 같은 명령을 돌려 목록을 비교한다.

```bash
# 변경 전 목록 (작업 브랜치를 건드리지 않도록 worktree 사용)
# 기준 커밋 = 이 브랜치의 분기점 24e4ca46 (git merge-base 로 확인)
git worktree add --detach /tmp/baseline-wt 24e4ca46
ln -s "$PWD/webapp/node_modules" /tmp/baseline-wt/webapp/node_modules
(cd /tmp/baseline-wt/webapp && npx jest --coverage=false --silent) 2>&1 | grep '^FAIL ' | sort > /tmp/fail-before.txt

# 변경 후 목록
(cd webapp && npx jest --coverage=false --silent) 2>&1 | grep '^FAIL ' | sort > /tmp/fail-after.txt

diff /tmp/fail-before.txt /tmp/fail-after.txt   # 차이가 없어야 한다
```

특히 **칸반 스위트가 목록에 새로 등장하면 FR-030 위반**이다.

## 플러그인 배포

webapp watch를 켜 두면 저장할 때마다 자동 배포된다.

```bash
cd webapp && npm run debug:watch
```

**`webpack.config.js`를 고쳤다면 watch를 재시작해야 한다** — 실행 중인 webpack은 자기 설정 파일을 다시 읽지 않는다. 이번 변경에는 webpack 설정 변경이 없지만, 배포됐는데 반영이 안 되면 이것부터 의심한다.

배포 후 브라우저 하드 리프레시가 필요하다(번들 경로에 콘텐츠 해시가 박힌다).

## 수동 확인

각 항목은 명세의 인수 시나리오에 대응한다. 하나라도 실패하면 완료가 아니다.

### A. 순서 이동과 인디케이터 (US1)

| # | 하는 일 | 봐야 하는 것 |
|---|---|---|
| A1 | 표의 행에 마우스를 올린다 | 왼쪽에 드래그 핸들이 나타난다 |
| A2 | 핸들에 커서를 올린다 | 커서가 `grab`으로 바뀌고 핸들에 배경이 생긴다 |
| A3 | 핸들을 잡아 다른 행의 **위쪽 절반**으로 끈다 | 그 행 **위**에 선이 그려진다 |
| A4 | 같은 행의 **아래쪽 절반**으로 내린다 | 선이 그 행 **아래**로 옮겨간다 |
| A5 | 놓는다 | 카드가 선이 있던 자리로 이동하고 선이 사라진다 |
| A6 | Ctrl+Z | 순서가 **한 번에** 되돌아온다 |
| A7 | 행의 제목 글자를 드래그한다 | 카드가 끌리지 않고 텍스트가 선택된다 |
| A8 | 행이 화면을 넘는 표에서, 드래그한 채로 표를 위아래로 스크롤한다 | 선이 스크롤과 함께 움직여 **항상 목표 경계에 붙어 있다** (FR-009) |
| A9 | 카드 여러 개를 선택한 뒤 그중 하나의 핸들로 끌어 순서를 바꾼다 | 선택한 카드가 전부 함께 이동한다 (FR-031) |

A7이 이번 변경의 부수 효과다. 지금은 제목을 끌면 행이 딸려 나온다.

**A8과 A9는 자동 테스트가 없는 유일한 확인 경로다.** A8(스크롤 좌표계)은 research R6이 "좌표계 선택으로 공짜"라 판단한 항목이라 코드에 방어가 없고, A9(다중 선택)는 드롭 핸들러를 갈아끼우면서 조용히 잃기 쉬운 기존 동작이다.

### B. 계층 이동 (US2)

| # | 하는 일 | 봐야 하는 것 |
|---|---|---|
| B1 | 최상위 카드를 끌어 윗 카드 아래 경계에서 커서를 **오른쪽으로** 민다 | 선이 한 단계 들여쓰기된다 |
| B2 | 그대로 놓는다 | 윗 카드의 하위가 되고, 윗 카드가 펼쳐진 상태로 보인다 |
| B3 | 하위 카드를 끌어 커서를 **왼쪽으로** 당긴다 | 선의 들여쓰기가 풀린다 |
| B4 | 그대로 놓는다 | 최상위 카드가 된다 |
| B5 | Ctrl+Z | 계층과 순서가 **한 번에** 되돌아온다 |
| B6 | 카드를 자기 자신 바로 앞/뒤 경계로 끈다 | 선이 그려지지 않고 커서가 `no-drop`이 된다 |
| B7 | 하위 카드를 거느린 카드를 끌어 자기 자손 사이로 넣으려 한다 | 선이 그려지지 않는다 |

### C. 서브트리 이동 (US3)

| # | 하는 일 | 봐야 하는 것 |
|---|---|---|
| C1 | 하위 카드 2개를 거느린 카드를 만든다 | |
| C2 | 그 카드를 끈다 | 하위 2개도 함께 흐려진다 |
| C3 | 다른 자리에 놓는다 | 하위 2개가 순서·계층을 유지한 채 따라온다 |
| C4 | 하위를 접은 뒤 부모를 옮긴다 | 펼쳐보면 하위가 그대로 따라와 있다 |
| C5 | 3단 서브트리(자기 포함)를 깊이 4가 될 자리로 끈다 | 그 깊이로는 선이 그려지지 않는다 |
| C6 | 같은 부모 안에서 하위 카드끼리 순서를 바꾼다 | 바뀐 순서가 **새로고침 후에도** 유지된다 |

C6이 design.md B3의 회귀 확인이다. 새로고침을 반드시 한다 — 고치기 전에는 화면에만 반영되고 저장 순서와 어긋난다.

## 완료 조건

- `make webapp-ci`의 실패 스위트 목록이 기준과 같다
- A~G 전 항목 통과
- 위 결과를 근거로 제시한 뒤에만 완료를 선언한다 (constitution 원칙 I)
