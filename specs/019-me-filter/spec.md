# Feature Specification: 사용자 속성 필터에 "본인" 조건을 더한다

**Feature Branch**: `019-me-filter`

**Created**: 2026-10-12

**Status**: Draft

**Input**: User description: "사용자, 다중 사용자, 만든 사람 등 사용자를 선택하는 속성을 필터로 사용할 때 본인을 선택하는 조건을 추가하여 로그인한 사용자로 자동 필터가 될 수 있도록 기능 추가"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 필터에서 "본인"을 선택한다 (Priority: P1)

담당자별 카드가 섞여 있는 보드에서 사용자가 필터를 연다. 담당자 속성의 사용자 목록 맨 위에 "본인" 항목이 있다. 이것을 체크하면 특정 이름을 찾아 고를 필요 없이 자기 카드만 남는다.

**Why this priority**: 기능의 본체다. 지금은 매번 자기 이름을 목록에서 찾아 선택해야 하고, 이름이 많은 조직일수록 비용이 크다.

**Independent Test**: 담당자가 서로 다른 카드 2장을 만들고, 필터에서 "본인"만 체크 → 자기 카드만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자 선택형 속성(사용자·다중 사용자·만든 사람·수정한 사람)으로 필터를 여는 상황, **When** 값 목록을 보면, **Then** 실제 사용자들 위에 "본인" 항목이 맨 위에 보인다.
2. **Given** 담당자가 나인 카드와 다른 사람인 카드가 섞인 보드, **When** "본인"을 체크하면, **Then** 내가 담당자인 카드만 남는다.
3. **Given** "본인"이 체크된 필터, **When** "본인" 체크를 해제하면, **Then** 필터가 걸리기 전 목록으로 돌아간다.
4. **Given** 사용자 검색창에 "본인"(또는 그 영문 표기)을 입력, **When** 목록이 좁혀지면, **Then** "본인" 항목이 검색 결과에 남는다.
5. **Given** "본인"과 특정 사용자 1명을 함께 체크, **When** 목록을 보면, **Then** 둘 중 하나라도 해당하는 카드가 보인다 (기존 다중 선택 의미 유지).

---

### User Story 2 - 공유 뷰에서 각자 자기 카드를 본다 (Priority: P2)

팀장이 "내 작업" 뷰를 만들며 담당자 필터를 "본인"으로 걸어 둔다. 팀원 누구가 그 뷰를 열어도 각자 **자기가 담당자인 카드만** 보인다. 특정 사람의 ID가 박제되지 않는다.

**Why this priority**: "본인"이 단순한 선택 편의를 넘어 가치를 내는 지점이다. 뷰 하나로 전 팀원의 "내 작업" 화면이 된다. US1이 전제라 P2.

**Independent Test**: 사용자 A가 "본인" 필터 뷰를 만들고, 사용자 B로 로그인해 같은 뷰를 열면 B의 카드만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자 A가 담당자 필터를 "본인"으로 저장한 뷰, **When** 사용자 B가 그 뷰를 열면, **Then** B가 담당자인 카드만 보인다.
2. **Given** 같은 뷰, **When** A가 다시 열면, **Then** A가 담당자인 카드만 보인다 — 뷰 설정은 바뀌지 않았다.
3. **Given** "본인" 필터가 걸린 뷰, **When** 필터 패널을 다시 열면, **Then** 체크된 항목이 특정 사용자 이름이 아니라 "본인"으로 표시된다.

---

### Edge Cases

- "본인" + "제외(does not include)" 조건 조합 → 내가 아닌 사람의 카드만 남는다. 기존 조건 의미를 그대로 따른다.
- 다중 사용자 속성에서 여러 명 중 한 명이 나인 카드 → "본인" 필터에 걸린다 (포함 판정).
- 담당자가 비어 있는 카드 → "본인" 필터에서 제외된다 (기존 포함 판정과 동일).
- 사용자 ID와 "본인" 토큰의 충돌 → 시스템 사용자 ID 형식과 겹치지 않는 예약 값을 쓴다.
- 이 기능이 없는 과거 버전 화면에서 "본인" 필터가 저장된 뷰를 열면 → 해당 조건이 아무 카드와도 일치하지 않을 뿐, 화면이 깨지지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자 선택형 속성(사용자, 다중 사용자, 만든 사람, 수정한 사람)의 필터 값 목록 맨 위에 "본인" 항목을 제공해야 한다.
- **FR-002**: "본인"을 선택하면 필터는 로그인한 사용자를 기준으로 평가되어야 한다 — 특정 사용자 ID를 저장하지 않는다.
- **FR-003**: "본인" 조건이 저장된 뷰를 다른 사용자가 열면 그 사용자 자신을 기준으로 평가되어야 한다.
- **FR-004**: "본인"은 다른 사용자 선택과 함께 쓸 수 있어야 하며, 포함/제외 등 기존 조건 의미를 그대로 따라야 한다.
- **FR-005**: 필터 패널에 체크 상태를 다시 표시할 때 "본인"은 사용자 이름이 아니라 "본인" 라벨로 보여야 한다.
- **FR-006**: 사용자 검색창에서 "본인" 라벨(한국어·영어)로 검색해도 항목이 찾아져야 한다.
- **FR-007**: "본인" 라벨은 한국어·영어 번역을 모두 제공해야 한다.
- **FR-008**: 기존 필터 동작(실제 사용자 선택, 다른 속성 유형의 필터)은 변경 없이 유지되어야 한다.

### Key Entities

- **"본인" 필터 토큰**: 뷰의 필터 값 목록에 저장되는 예약 값. 특정 사용자를 가리키지 않고, 카드 목록을 그리는 시점에 보는 사람의 계정으로 풀이된다. 실제 사용자 ID와 충돌하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 자기 카드만 보는 필터를 클릭 2번(필터 속성 선택 → "본인" 체크) 안에 걸 수 있다 — 이름 검색·스크롤 불필요.
- **SC-002**: "본인" 필터 뷰를 서로 다른 두 계정으로 열었을 때, 각자 자기가 해당하는 카드만 보인다 (교차 노출 0건).
- **SC-003**: 사용자 선택형 속성 4종(사용자·다중 사용자·만든 사람·수정한 사람) 모두에서 "본인" 필터가 동작한다.
- **SC-004**: 기존 필터 자동 테스트가 전부 통과하고, 실제 사용자 선택 필터의 동작이 변경 전과 동일하다.

## Assumptions

- 적용 범위는 보드 필터 패널(카드 필터)이다. 카드 속성 편집기의 "Me" 선택(현재도 존재, 실제 ID 저장)은 그대로 둔다 — 속성 값은 특정 사람에게 고정되는 것이 맞다.
- "본인" 항목은 로그인 상태에서만 의미가 있다. 공개(비로그인) 공유 화면에서는 "본인" 조건이 아무 카드와도 일치하지 않는 것을 허용한다.
- 필터 평가가 화면을 그리는 쪽에서 이루어지는 현 구조를 유지한다. 서버 변경은 없다.
- 구형 필터 UI 컴포넌트(현재 어디서도 쓰이지 않는 레거시)는 범위에서 제외한다.
