# Feature Specification: 뷰마다 권한 모드를 정한다 (관리자 · 공용 · 개인)

**Feature Branch**: `022-view-permission`

**Created**: 2026-11-02

**Status**: Draft

**Input**: User description: "보드 뷰 권한 (관리자 · 공용 · 개인). 뷰 헤더의 속성·그룹화·필터·정렬 메뉴 뒤에 권한 메뉴를 추가한다. 공용(기본값)은 지금처럼 보드 편집 권한자 누구나 뷰 구성을 바꾼다. 관리자는 보드 접근자 모두에게 뷰가 보이지만 뷰 구성은 관리자만 바꾸고, 카드 순서 변경·카드 끌어 옮기기·검색·그룹 접기·열 너비·뷰 복제는 팀원에게 열어 둔다. 개인은 뷰를 만든 사람에게만 보이고 서버가 걸러 낸다. 권한 메뉴에서 관리자 항목은 관리자에게만, 개인 항목은 뷰를 만든 사람에게만 보인다. 관리자는 탭에서 남의 개인 뷰를 볼 수 없고, 공유 위젯의 관리자 영역에서 개인 뷰 목록만 본다. 상세 설계는 브레인스토밍 초안(docs/superpowers/specs/2026-11-02-view-permission-design.md)을 따른다."

## 왜 지금이 문제인가

팀 정책상 모든 구성원이 같은 모습으로 봐야 하는 뷰가 있다. 어떤 속성을 보이고, 무엇으로
묶고, 어떤 필터를 거는지가 곧 정책이다. 지금은 보드 편집 권한만 있으면 누구나 이 구성을
바꾼다. 팀원 한 명이 필터를 손대면 전원의 화면이 바뀌고 정책에 혼선이 생긴다.

반대로, 자기 작업용으로 만든 뷰는 남에게 보일 이유가 없다. 지금은 뷰를 만들면 무조건
보드의 모든 사용자에게 탭으로 노출되어 탭 줄이 길어지고 어느 것이 공식 뷰인지 흐려진다.

뷰마다 권한 모드를 하나 고르게 해서 두 문제를 함께 푼다.

## 세 가지 모드

| 모드 | 누가 보는가 | 누가 구성을 바꾸는가 |
|---|---|---|
| 공용 (기본값) | 보드 접근 권한이 있는 모두 | 지금과 같다 — 보드 편집 권한이 있는 모두 |
| 관리자 | 보드 접근 권한이 있는 모두 | 관리자 등급만 |
| 개인 | 뷰를 만든 사람만 | 뷰를 만든 사람만 |

"뷰 구성"은 모두의 화면을 바꾸는 설정이다. 표시 속성, 그룹화, 필터, 정렬, 달력의 날짜
기준, 칸반 열 숨김, 열 계산식, 기본 카드 템플릿, 뷰 이름, 뷰 삭제, 그리고 모드 변경
자체다.

"카드 쪽 동작"은 잠그지 않는다. 카드를 다른 열로 끌어 옮기기, 같은 열이나 표 안에서
카드 순서 바꾸기, 검색, 표 그룹 접기, 열 너비 조절, 뷰 복제다. 카드 순서는 뷰에 저장되어
모두에게 보이지만 사용자가 "막을 필요 없다"고 정했다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자가 뷰를 잠근다 (Priority: P1) 🎯 MVP

보드 관리자가 정책 뷰의 권한 메뉴에서 "관리자"를 고른다. 그 순간부터 팀원은 그 뷰를
보고 카드를 다루지만, 표시 속성·그룹화·필터·정렬 같은 뷰 구성은 바꾸지 못한다. 화면을
거치지 않은 요청도 서버가 거절한다.

**Why this priority**: 이 기능의 핵심이다. 관리자 모드가 실제로 막지 못하면 나머지는
의미가 없다.

**Independent Test**: 관리자로 뷰를 관리자 모드로 바꾼 뒤 팀원으로 로그인해 필터를
바꾸려 하면 거절되고, 같은 뷰에서 카드를 다른 열로 끌어 옮기면 성공한다.

**Acceptance Scenarios**:

1. **Given** 관리자 모드인 뷰, **When** 팀원이 표시 속성·그룹화·필터·정렬·날짜 기준을 바꾸려 하면, **Then** 거절된다
2. **Given** 관리자 모드인 뷰, **When** 팀원이 칸반 열을 숨기거나 계산식을 바꾸거나 기본 카드 템플릿을 정하려 하면, **Then** 거절된다
3. **Given** 관리자 모드인 뷰, **When** 팀원이 뷰 이름을 바꾸거나 뷰를 지우려 하면, **Then** 거절된다
4. **Given** 관리자 모드인 뷰, **When** 팀원이 카드를 다른 열로 끌어 옮기면, **Then** 성공하고 카드 속성이 바뀐다
5. **Given** 관리자 모드인 뷰, **When** 팀원이 같은 열 안이나 표 안에서 카드 순서를 바꾸면, **Then** 성공한다
6. **Given** 관리자 모드인 뷰, **When** 팀원이 검색하거나 표 그룹을 접거나 열 너비를 조절하면, **Then** 성공하고 자기 화면에만 적용된다
7. **Given** 관리자 모드인 뷰, **When** 팀원이 뷰를 복제하면, **Then** 성공하고 사본은 공용 모드로 만들어진다
8. **Given** 관리자 모드인 뷰, **When** 관리자가 위 어떤 뷰 구성이든 바꾸면, **Then** 성공한다
9. **Given** 관리자 모드인 뷰, **When** 팀원이 화면을 거치지 않고 뷰 구성 변경 요청을 직접 보내면, **Then** 거절된다

---

### User Story 2 - 모드를 정한 적 없는 뷰는 달라지지 않는다 (Priority: P1)

모드를 한 번도 고른 적 없는 뷰는 공용이다. 기존 뷰는 전부 공용으로 남고, 새로 만드는
뷰도 공용으로 시작한다. 공용 뷰에서는 지금까지 하던 대로 보드 편집 권한이 있는 누구나
뷰 구성을 바꾼다.

**Why this priority**: 회귀가 나면 안 되는 자리다. 이 기능은 기존 보드의 동작을 한 톨도
바꾸지 않아야 한다.

**Independent Test**: 모드를 고른 적 없는 뷰에서 팀원이 필터를 바꾸면 성공하고, 뷰가
모두에게 보인다.

**Acceptance Scenarios**:

1. **Given** 모드를 고른 적 없는 뷰, **When** 팀원이 뷰 구성을 바꾸면, **Then** 성공한다
2. **Given** 모드를 고른 적 없는 뷰, **When** 어떤 보드 사용자든 보드를 열면, **Then** 그 뷰가 탭에 보인다
3. **Given** 관리자 모드였다가 공용으로 되돌린 뷰, **When** 팀원이 뷰 구성을 바꾸면, **Then** 성공한다
4. **Given** 새로 만든 뷰, **When** 권한 메뉴를 열면, **Then** 현재 모드가 공용이다

---

### User Story 3 - 뷰를 만든 사람이 개인 뷰로 돌린다 (Priority: P2)

뷰를 만든 사람이 권한 메뉴에서 "개인"을 고른다. 그 뷰는 만든 사람에게만 탭으로 보이고,
다른 사용자에게는 존재하지 않는 것처럼 보인다. 서버가 걸러 보내므로 다른 사용자의
브라우저에는 뷰 자체가 도착하지 않는다.

**Why this priority**: 정책 뷰 잠금(US1)과 별개로 가치가 있다. 탭 줄을 정리하고 작업용
뷰를 숨긴다.

**Independent Test**: A가 자기 뷰를 개인으로 바꾼 뒤 B로 로그인하면 그 뷰가 탭에 없고,
뷰 주소로 직접 들어가도 열리지 않는다.

**Acceptance Scenarios**:

1. **Given** A가 만든 공용 뷰, **When** A가 개인으로 바꾸면, **Then** A에게는 계속 보이고 B의 탭에서는 사라진다
2. **Given** A의 개인 뷰, **When** B가 보드 데이터를 받으면, **Then** 그 뷰는 들어 있지 않다
3. **Given** A의 개인 뷰, **When** B가 그 뷰의 주소로 직접 들어가면, **Then** 첫 번째 보이는 뷰로 떨어진다
4. **Given** A의 개인 뷰, **When** B가 그 뷰를 바꾸거나 지우거나 복제하거나 복원하는 요청을 직접 보내면, **Then** 거절된다
5. **Given** A의 개인 뷰, **When** A가 뷰 구성을 바꾸면, **Then** 성공한다
6. **Given** A의 개인 뷰, **When** A가 공용으로 되돌리면, **Then** B의 탭에 뷰가 나타난다
7. **Given** A의 개인 뷰, **When** 관리자가 보드를 열면, **Then** 탭에 그 뷰가 없다

---

### User Story 4 - 권한 메뉴는 고를 수 있는 것만 보여 준다 (Priority: P2)

권한 메뉴는 뷰 헤더에서 속성·그룹화·필터·정렬 메뉴 뒤에 붙는다. 버튼에는 현재 모드가
보인다. 열면 그 사용자가 고를 수 있는 항목만 보인다. 관리자 항목은 관리자에게만, 개인
항목은 뷰를 만든 사람에게만 보인다. 팀원이 관리자 뷰를 공용으로 되돌리거나, 남의 공용
뷰를 개인으로 돌릴 수는 없다.

**Why this priority**: 이것이 없으면 US1·US3의 제한이 형식뿐이다. 다만 US1·US3이 먼저
있어야 의미가 생기므로 P2다.

**Independent Test**: 같은 뷰의 권한 메뉴를 관리자·만든 사람·일반 팀원 세 계정으로 열어
항목이 각각 다르게 보이고, 화면 밖에서 보낸 전환 요청도 같은 규칙으로 거절되는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 어떤 뷰, **When** 관리자가 권한 메뉴를 열면, **Then** 관리자 항목이 보인다
2. **Given** 어떤 뷰, **When** 관리자가 아닌 사용자가 권한 메뉴를 열면, **Then** 관리자 항목이 없다
3. **Given** 어떤 뷰, **When** 뷰를 만든 사람이 권한 메뉴를 열면, **Then** 개인 항목이 보인다
4. **Given** 남이 만든 뷰, **When** 만든 사람이 아닌 사용자가 권한 메뉴를 열면, **Then** 개인 항목이 없다
5. **Given** 관리자 모드인 뷰, **When** 팀원이 공용으로 바꾸는 요청을 보내면, **Then** 거절된다
6. **Given** 남이 만든 공용 뷰, **When** 팀원이 개인으로 바꾸는 요청을 보내면, **Then** 거절된다
7. **Given** 어떤 뷰, **When** 관리자가 아닌 사용자가 관리자로 바꾸는 요청을 보내면, **Then** 거절된다
8. **Given** 자기가 만든 개인 뷰이고 사용자가 관리자이기도 할 때, **When** 관리자로 바꾸면, **Then** 성공한다
9. **Given** 바꿀 수 있는 항목이 없는 사용자, **When** 권한 버튼을 보면, **Then** 현재 모드가 적힌 채 비활성이고 안내 문구가 있다

---

### User Story 5 - 잠긴 뷰에서는 잠긴 조작이 화면에서 비활성이다 (Priority: P3)

관리자 모드인 뷰를 보는 팀원에게는 속성·그룹화·필터·정렬·날짜 기준 메뉴가 비활성이고,
왜 비활성인지 안내 문구가 붙는다. 뷰 탭 메뉴에서 이름 변경·삭제가 사라지고 복제만
남는다. 카드 쪽 동작은 그대로다.

**Why this priority**: 서버가 막으면 정책은 지켜진다. 화면은 팀원이 헛수고하지 않게
한다. 없으면 기능은 동작하되 쓰기 나쁘다.

**Independent Test**: 관리자 모드인 뷰를 팀원으로 열면 뷰 구성 메뉴가 비활성이고 안내
문구가 있으며, 같은 뷰를 관리자로 열면 모두 활성이다.

**Acceptance Scenarios**:

1. **Given** 관리자 모드인 뷰를 보는 팀원, **When** 뷰 헤더를 보면, **Then** 속성·그룹화·필터·정렬·날짜 기준 메뉴가 비활성이고 "이 뷰는 관리자만 수정할 수 있다"는 뜻의 안내가 있다
2. **Given** 관리자 모드인 뷰를 보는 팀원, **When** 뷰 탭 메뉴를 열면, **Then** 이름 변경·삭제가 없고 복제는 있다
3. **Given** 관리자 모드인 뷰를 보는 팀원, **When** 새 카드 메뉴에서 기본 템플릿 지정을 보면, **Then** 비활성이다
4. **Given** 관리자 모드인 뷰를 보는 팀원, **When** 카드를 끌거나 검색하거나 그룹을 접거나 열 너비를 조절하면, **Then** 모두 동작한다
5. **Given** 관리자 모드인 뷰를 보는 관리자, **When** 같은 화면을 보면, **Then** 모든 조작이 활성이다
6. **Given** 팀원이 보고 있는 공용 뷰, **When** 관리자가 그 뷰를 관리자 모드로 바꾸면, **Then** 팀원의 메뉴가 새로고침 없이 비활성으로 바뀐다

---

### User Story 6 - 관리자가 개인 뷰 목록을 보고 정리한다 (Priority: P3)

개인 뷰를 만든 사람이 퇴사하거나 보드를 떠나면 그 뷰는 아무도 볼 수 없는 채로 남는다.
관리자는 공유 위젯의 관리자 영역에서 이 보드의 개인 뷰 목록을 본다. 뷰 이름, 만든 사람,
만든 날짜, 삭제 버튼만 있다. 뷰 구성 내용은 보여 주지 않고 탭에도 나타나지 않는다.

**Why this priority**: 운영 정리 경로다. 없어도 US3은 동작하지만, 없으면 고아 뷰가
영원히 남는다.

**Independent Test**: A가 개인 뷰를 만든 뒤 관리자로 공유 위젯을 열면 목록에 그 뷰가
이름·만든 사람·날짜와 함께 있고, 삭제하면 A의 탭에서도 사라진다.

**Acceptance Scenarios**:

1. **Given** 개인 뷰가 있는 보드, **When** 관리자가 공유 위젯을 열면, **Then** 개인 뷰 목록 섹션에 이름·만든 사람·만든 날짜가 보인다
2. **Given** 개인 뷰가 있는 보드, **When** 관리자가 아닌 사용자가 공유 위젯을 열면, **Then** 개인 뷰 목록 섹션이 없다
3. **Given** 개인 뷰 목록, **When** 관리자가 삭제를 누르면, **Then** 확인을 거친 뒤 뷰가 지워지고 만든 사람의 탭에서도 사라진다
4. **Given** 개인 뷰 목록, **When** 관리자가 항목을 보면, **Then** 필터·정렬 같은 뷰 구성 내용은 없다
5. **Given** 개인 뷰가 있는 보드, **When** 관리자가 아닌 사용자가 목록 조회나 삭제 요청을 직접 보내면, **Then** 거절된다
6. **Given** 개인 뷰가 없는 보드, **When** 관리자가 공유 위젯을 열면, **Then** 섹션은 비어 있다고 알린다

---

### Edge Cases

- **마지막 비개인 뷰 보호.** 보드에 남은 공용·관리자 뷰가 하나뿐이면 그 뷰를 개인으로
  바꾸거나 지울 수 없다. 허용하면 다른 모든 사용자에게 뷰가 0개인 보드가 된다. 화면은
  개인 항목과 삭제를 숨기고, 서버도 거절한다. 지금 "마지막 뷰 삭제 금지"는 화면에만 있고
  보이는 뷰 수로 세는데, 내 개인 뷰도 거기 들어가므로 셈을 비개인 뷰 수로 바꾼다.
- **저장된 모드 값을 읽을 수 없을 때.** 세 모드 중 어느 것으로도 읽히지 않는 값은 공용으로
  취급한다. 반쯤 이해한 값을 잠금으로 읽으면 아무도 잠그지 않은 뷰가 잠긴다.
- **보드 복제 · 템플릿에서 보드 만들기.** 공용·관리자 뷰는 모드를 그대로 들고 복사된다.
  개인 뷰는 복제하는 사람이 만든 것만 복사되고, 남의 개인 뷰는 빠진다. 그대로 복사하면
  남의 개인 뷰 구성이 복제한 사람의 손에 넘어간다.
- **보드 내보내기.** 내보낸 사람이 볼 수 없는 개인 뷰는 아카이브에 들어가지 않는다.
  관리자가 내보내도 남의 개인 뷰는 빠지고, 복원하면 사라진다. 개인 뷰는 만든 사람의
  것이므로 받아들인다.
- **공용에서 개인으로 바꾸는 순간 그 뷰를 보고 있던 다른 사용자.** 새로고침 없이 탭이
  사라지고 첫 번째 보이는 뷰로 떨어진다. 이때 다른 사용자에게는 뷰의 내용이 아니라 "이
  뷰가 사라졌다"는 신호만 간다.
- **공용에서 관리자로 바꾸는 순간 그 뷰를 보고 있던 팀원.** 새로고침 없이 메뉴가
  비활성으로 바뀐다. 이미 열어 둔 화면에서 보낸 변경도 서버가 거절한다.
- **개인 뷰를 공용으로 되돌림.** 다른 사용자에게는 뷰가 새로 생긴 것처럼 나타난다.
- **개인 뷰 쓰기 우회.** 바꾸기와 지우기뿐 아니라 복제, 복원, 같은 식별자로 다시 넣기도
  만든 사람 외에는 거절한다. 복제를 열어 두면 사본으로 내용을 읽어 갈 수 있다.
- **개인 뷰 주소로 직접 접근.** 첫 번째 보이는 뷰로 떨어진다. 지금은 모르는 뷰 주소를
  열면 빈 화면이 되므로(리다이렉트는 주소에 뷰가 없을 때만 동작한다), 이 기능이 "보이는
  뷰 목록에 없는 주소"의 fallback을 더한다. 마지막에 본 뷰 기억이 숨겨진 뷰를 가리킬 때도
  같다.
- **개인 뷰를 만든 사람이 보드를 떠남.** 뷰는 남고 아무에게도 보이지 않는다. 관리자가
  개인 뷰 목록에서 지운다(US6).
- **뷰 복제 사본.** 원본이 어떤 모드든 사본은 복제한 사람이 만든 새 뷰이고 공용으로
  시작한다.
- **관리자 모드 뷰에서 팀원이 칸반 열 순서를 바꿈.** 열 순서는 뷰 구성이므로 잠긴다.
  카드 순서와 다르다.

## Requirements *(mandatory)*

### Functional Requirements

**모드와 기본값**

- **FR-001**: 뷰는 권한 모드 하나를 기억한다. 값은 공용, 관리자, 개인 중 하나다.
- **FR-002**: 모드를 정한 적 없는 뷰는 공용이다. 기존 뷰는 전부 공용으로 시작하고, 새로 만드는 뷰도 공용으로 시작한다.
- **FR-003**: 저장된 모드가 세 값 중 어느 것으로도 읽히지 않으면 공용으로 취급한다.
- **FR-004**: 공용 뷰의 보기·구성 변경 권한은 이 기능이 없던 때와 동일하다.

**관리자 모드**

- **FR-005**: 관리자 모드인 뷰는 보드 접근 권한이 있는 모두에게 보인다.
- **FR-006**: 관리자 모드인 뷰의 구성(표시 속성, 그룹화, 필터, 정렬, 날짜 기준, 칸반 열 숨김과 순서, 열 계산식, 기본 카드 템플릿, 뷰 이름)을 바꾸는 일은 관리자 등급에게만 허용한다.
- **FR-007**: 관리자 모드인 뷰를 지우는 일은 관리자 등급에게만 허용한다.
- **FR-008**: 관리자 모드인 뷰에서도 카드 순서 변경은 보드 편집 권한이 있는 모두에게 허용한다. 카드 순서만 바꾸는 요청은 통과시키고, 카드 순서와 함께 다른 구성을 바꾸는 요청은 거절한다.
- **FR-009**: 관리자 모드인 뷰에서 카드를 끌어 옮기기, 검색, 표 그룹 접기, 열 너비 조절, 뷰 복제는 지금 권한 그대로 둔다.

**개인 모드**

- **FR-010**: 개인 모드인 뷰는 그 뷰를 만든 사람에게만 보인다. 다른 사용자에게는 보드 데이터를 내려보낼 때와 실시간 갱신을 보낼 때 모두 그 뷰를 뺀다.
- **FR-011**: 개인 모드인 뷰를 바꾸기, 지우기, 복제하기, 복원하기, 같은 식별자로 다시 넣기는 만든 사람에게만 허용한다. 예외는 FR-023의 관리자 정리 경로 하나다.
- **FR-012**: 관리자 등급도 탭에서는 남의 개인 뷰를 보지 못한다 (FR-010의 강조 — 사용자가 정한 사항).
- **FR-013**: 개인 뷰로 바뀌는 순간, 만든 사람 외의 사용자에게는 그 뷰가 사라졌다는 신호만 보내고 뷰 내용은 보내지 않는다.
- **FR-014**: 보이지 않는 뷰의 주소로 들어가거나, 보고 있던 뷰가 보이지 않게 되면 첫 번째 보이는 뷰로 보낸다. 마지막에 본 뷰 기억이 보이지 않는 뷰를 가리켜도 같다.

**모드 전환 규칙**

- **FR-015**: 모드를 바꾸려면 현재 모드의 뷰를 건드릴 권한과 목표 모드를 고를 권한을 둘 다 가져야 한다. 공용 뷰는 보드 편집 권한자가 건드리고 누구나 공용을 고른다. 관리자 뷰는 관리자 등급만 건드리고 관리자 등급만 관리자를 고른다. 개인 뷰는 만든 사람만 건드리고 만든 사람만 개인을 고른다.
- **FR-016**: 보드에 남은 비개인(공용·관리자) 뷰가 하나뿐이면 그 뷰를 개인으로 바꾸거나 지우는 요청은 누구의 것이든 거절한다.
- **FR-017**: 서버가 FR-005~FR-011, FR-013, FR-015, FR-016을 강제한다. 화면을 거치지 않은 요청도 같은 답을 받는다.
- **FR-018**: 뷰를 바꾸는 모든 요청 경로에서 같은 판정을 한다. 한 경로만 막으면 다른 경로로 같은 변경이 통과한다.

**권한 메뉴 화면**

- **FR-019**: 뷰 헤더에서 속성·그룹화·필터·정렬 메뉴 뒤에 권한 메뉴를 둔다. 버튼에 현재 모드 이름이 보인다.
- **FR-020**: 권한 메뉴에는 그 사용자가 FR-015에 따라 고를 수 있는 항목만 보인다. 고를 수 없는 항목은 비활성이 아니라 없다. 관리자 항목은 관리자 등급에게만, 개인 항목은 뷰를 만든 사람에게만 보인다. FR-016에 걸리면 개인 항목도 없다.
- **FR-021**: 바꿀 수 있는 항목이 현재 모드 하나뿐이거나 전혀 없는 사용자에게는 버튼을 비활성으로 보여 주고 안내 문구를 붙인다. 버튼은 숨기지 않는다.

**잠긴 조작의 화면 처리**

- **FR-022**: 관리자 모드인 뷰를 보는 비관리자에게는 뷰 구성 메뉴(표시 속성, 그룹화, 필터, 정렬, 날짜 기준, 기본 템플릿 지정)를 비활성으로 보여 주고 "이 뷰는 관리자만 수정할 수 있다"는 뜻의 안내를 붙인다. 뷰 탭 메뉴에서는 이름 변경·삭제를 숨기고 복제는 남긴다. 칸반 열 끌기는 막고 열 숨기기·숨긴 열 보이기 항목은 숨긴다. 카드 쪽 동작의 조작은 그대로 보여 준다.

**관리자용 개인 뷰 목록**

- **FR-023**: 관리자 등급은 공유 위젯의 관리자 영역에서 이 보드의 모든 개인 뷰 목록을 본다. 항목마다 뷰 이름, 만든 사람, 만든 날짜, 삭제 버튼이 있다. 뷰 구성 내용은 보여 주지 않는다.
- **FR-024**: 관리자 등급은 목록에서 개인 뷰를 지울 수 있다. 삭제 전에 확인을 받는다. 공용으로 바꾸는 기능은 두지 않는다.
- **FR-025**: 개인 뷰 목록 조회와 삭제는 관리자 등급에게만 허용하고 서버가 강제한다.

**복제 · 내보내기**

- **FR-026**: 뷰를 복제하면 사본은 복제한 사람이 만든 새 뷰이고 원본 모드와 무관하게 공용으로 시작한다.
- **FR-027**: 보드를 복제하거나 템플릿에서 보드를 만들 때 공용·관리자 뷰는 모드를 그대로 들고 복사되고, 개인 뷰는 복제하는 사람이 만든 것만 복사된다.
- **FR-028**: 보드를 내보낼 때 내보낸 사람이 볼 수 없는 개인 뷰는 아카이브에 넣지 않는다.

**i18n**

- **FR-029**: 새로 추가하는 모든 표시 문자열(모드 이름, 안내 문구, 목록 섹션 제목, 확인 문구)은 한국어와 영어를 함께 제공한다.

### Key Entities

- **뷰 권한 모드**: 뷰가 기억하는 값 하나. 공용·관리자·개인 중 하나이고, 정한 적 없으면
  공용이다. 뷰의 다른 구성(필터·정렬 등)과 같은 자리에 산다.
- **뷰를 만든 사람**: 뷰가 이미 기억하는 작성자. 개인 모드의 보기·쓰기 권한과 개인 항목
  노출 여부를 이 값으로 판정한다.
- **관리자용 개인 뷰 목록**: 보드 단위로 관리자에게만 보이는 목록. 항목은 뷰 이름, 만든
  사람, 만든 날짜다. 뷰 구성 내용은 담지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자 모드인 뷰에서 비관리자가 시도하는 뷰 구성 변경은 종류를 불문하고 100% 거절된다 — 표시 속성, 그룹화, 필터, 정렬, 날짜 기준, 칸반 열 숨김과 순서, 계산식, 기본 템플릿, 이름 변경, 삭제 전부.
- **SC-002**: 관리자 모드인 뷰에서 비관리자가 카드를 끌어 옮기고 카드 순서를 바꾸는 일은 100% 성공한다.
- **SC-003**: 모드를 정한 적 없는 뷰에서 일어나는 모든 동작은 이 기능 도입 전과 결과가 동일하다.
- **SC-004**: 개인 뷰는 만든 사람 외의 어떤 사용자에게도 보드 데이터·실시간 갱신·주소 직접 접근 어느 경로로도 내용이 전달되지 않는다.
- **SC-005**: 만든 사람 외의 사용자가 개인 뷰에 보내는 쓰기 요청(바꾸기·지우기·복제·복원·다시 넣기)은 100% 거절된다.
- **SC-006**: 권한 메뉴에서 사용자가 고를 수 없는 항목은 화면에 하나도 보이지 않고, 화면 밖에서 보낸 같은 전환 요청도 거절된다.
- **SC-007**: 어떤 조작 순서로도 보드의 비개인 뷰가 0개가 되지 않는다.
- **SC-008**: 관리자는 공유 위젯에서 보드의 모든 개인 뷰를 이름·만든 사람·날짜로 확인하고 지울 수 있으며, 비관리자에게는 그 목록이 없다.
- **SC-009**: 보드 복제·템플릿 생성·내보내기 어느 경로로도 남의 개인 뷰 구성이 다른 사용자에게 넘어가지 않는다.

## Assumptions

- "관리자 등급"은 이 저장소가 속성 편집 잠금(010)에 쓰는 것과 같은 바를 뜻한다. 보드
  관리자, 시스템 관리자, 그리고 보드의 명시적 멤버인 팀 관리자가 통과한다. 플러그인의
  기존 권한 판정이 팀 관리자를 명시적 멤버일 때만 승격하므로 이 기능은 그 규칙을 바꾸지
  않는다.
- "뷰를 만든 사람"은 뷰가 이미 기억하는 작성자 정보를 그대로 쓴다. 서버가 뷰를 만들 때
  채우므로 새 저장 항목이 필요 없다.
- 모드의 기본값이 공용이므로 마이그레이션이 필요 없다. 기존 뷰는 값이 없는 상태로 남고
  그것이 곧 공용이다.
- 표 뷰의 그룹 접기와 열 너비는 021에서 이미 사용자별 로컬 상태로 분리되어 서버에
  저장되지 않는다. 그래서 관리자 모드에서 잠글 대상이 아니다.
- 개인 뷰를 거르는 자리는 카드 접근 권한(009)이 이미 쓰는 사용자별 블록 필터와 실시간
  갱신 수신자 필터를 재사용한다. 다만 그 필터는 카드 접근 규칙이 꺼진 보드에서 일찍
  끝나므로, 개인 뷰 판정은 그보다 앞에서 한다.
- 모드 변경은 뷰의 다른 구성 변경과 같은 방식으로 기록되고 다른 참여자에게 전달된다.
- 화면 처리는 지금 편집 권한이 없을 때 쓰는 비활성 버튼과 안내 문구 방식을 재사용하고,
  문구만 구분한다. 새 시각 요소를 만들지 않는다.

## 범위 밖

- 뷰를 특정 그룹·조직에만 보이게 하는 세분화된 읽기 권한. 세 모드가 전부다.
- 관리자가 탭에서 남의 개인 뷰를 보거나 편집하는 것.
- 개인 뷰를 관리자가 공용으로 전환하는 것.
- 기존 뷰를 자동으로 관리자 모드로 바꾸는 일괄 마이그레이션.
- 카드 자체의 권한(009·010)에 대한 변경.
- 모드 변경 이력을 따로 보여주는 화면.
- 관리자 모드에서 카드 순서 변경을 막는 것. 사용자가 막지 않기로 정했다.
