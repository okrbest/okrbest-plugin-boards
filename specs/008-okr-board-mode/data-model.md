# 데이터 모델: OKR Board로 사용

**Feature**: `008-okr-board-mode`

새 테이블도, 새 마이그레이션도, 새 엔드포인트도 없다. 이 문서는 **무엇이 저장되고
언제 무엇이 채워지는가**를 적는다.

---

## 1. 보드 설정

기존 보드 JSON에 키 하나가 붙는다.

```jsonc
// focalboard_boards.properties
{
  "propertyAccess": { /* 002 */ },
  "orgColors":      { /* 007 */ },
  "okrBoard": {
    "propertyId": "a6amddgmrzakw66cidqzgk6p4ge",
    "levels": [
      "auw3afh3kfhrfgmjr8muiz137jy",
      "apqfjst8massbjjhpcsjs3y1yqa",
      "axebhr7rpieabmowmg7ji9oogdh"
    ]
  }
}
```

| 규칙 | 값 |
|---|---|
| `propertyId` | 단계를 적는 선택 속성의 ID |
| `levels` | 단계별 **옵션 ID**. 0번이 1단계 |
| 켜지지 않은 보드 | 키 자체가 없다 |
| 끈 보드 | **키를 지운다** — 없는 것이 꺼진 상태다 |
| 검증 | 서버는 저장 시 하지 않는다. 읽을 때 형태를 확인한다 |

**이름을 저장하지 않는 것이 요점이다.** 사용자가 `Tasks`를 `할 일`로 바꿔도 옵션 ID는
그대로이므로 3단계가 계속 동작한다(FR-005).

**끄기를 "키 삭제"로 정한 이유**: `enabled: false`를 남기면 "꺼짐"과 "켠 적 없음"이
두 가지 표현을 갖는다. 읽는 쪽이 둘을 같게 다뤄야 하므로 표현을 하나로 줄인다.

---

## 2. 유형 속성

기존 `board.card_properties`의 선택 속성 하나다. 이 기능이 만들 수도, 이미 있던 것을
쓸 수도 있다.

| 상태 | 켤 때 하는 일 |
|---|---|
| 이름이 `유형`인 선택 속성이 있다 | 그것을 쓴다 |
| 그 속성에 값이 3개 미만이다 | 모자란 값을 뒤에 더한다 |
| 값 이름이 다르다 (`Object`) | **옵션 ID를 유지한 채 이름만 바꾼다** |
| 이름이 `유형`인데 선택 속성이 아니다 | 쓰지 않는다. 새로 만든다 |
| 없다 | `유형` 선택 속성을 만들고 값 셋을 넣는다 |

만든 뒤에는 보통 선택 속성과 다르지 않다. 값을 더하고, 이름을 바꾸고, 색을 고르고,
지울 수 있다. 이 기능이 잠그는 것은 없다.

**기본 값 이름**: `Objective`, `Key Results`, `Tasks`. 화면 언어와 무관하게 같은
문자열을 쓴다 — 번역하면 이미 만들어 둔 속성을 못 알아본다.

---

## 3. 채움 규칙

```
깊이 0 → levels[0]   (1단계, Objective)
깊이 1 → levels[1]   (2단계, Key Results)
깊이 2 이상 → levels[마지막]   (3단계 이상, Tasks)
```

깊이를 배열 인덱스로 쓰고, 배열 끝을 넘으면 마지막 항목을 쓴다. 최대 깊이가 늘어도
규칙이 그대로다.

**설정이 가리키는 옵션이 사라졌으면 그 단계는 채우지 않는다.** 사용자가 값을 지운
것은 결정이므로 없는 값을 되살리지 않는다.

---

## 4. 언제 채우는가

세 경로가 있고 판단 기준이 다르다.

| | 빈 카드 | 템플릿 카드 | 하위 카드 |
|---|---|---|---|
| 채우는 쪽 | 클라이언트 | 클라이언트 | 서버 |
| 깊이 | 새 카드라 0 | **복제된 카드에서 읽는다** | 부모 깊이 + 1 |
| 이미 값이 있으면 | **안 덮는다** — 필터·그룹이 정한 의도다 | **안 덮는다** — 템플릿에 박은 의도다 | **덮는다** — 부모에게서 복사된 값이다 |
| 부모 속성 상속 | 해당 없음 | 해당 없음 | 그대로 유지. 유형만 바뀐다 |

**템플릿 카드의 깊이를 0으로 가정하지 않는다.** 블록 복제가 `depth`와 `parentCardId`를
그대로 복사하고, 하위 카드에서도 템플릿을 만들 수 있다. 3단계 카드로 만든 템플릿은
`depth: 2`를 물려주므로 그 템플릿으로 만든 카드는 Tasks로 시작한다(FR-006a).

하위 카드에서 순서는 이렇다.

```
부모 속성 복사  →  OKR 단계 값  →  접근 규칙 기본값
```

접근 규칙이 마지막에 덮는다. 규칙은 권한이고 단계는 편의다([research.md](./research.md) R5).

---

## 5. 무엇이 안 바뀌나

- **이미 있는 카드**: 켜는 순간 소급하지 않는다.
- **만든 뒤의 값**: 사용자가 바꾸면 그대로다. 다시 계산하지 않는다.
- **카드를 옮길 때**: 부모가 바뀌어도 유형은 그대로다.
- **복제·가져오기·실행 취소**: 이 경로들은 채움을 타지 않는다.

---

## 6. 하위 호환

- **기존 보드**: `okrBoard` 키가 없다. 아무것도 달라지지 않는다.
- **보드 복제**: `properties`가 통째로 복제되므로 설정도 따라간다. 속성도 함께 복제되어
  옵션 ID가 유지되므로 설정이 그대로 유효하다.
- **구버전 클라이언트**: 키를 무시한다. 최상위 카드가 안 채워질 뿐이고, 하위 카드는
  서버가 채우므로 그대로 동작한다.
- **구버전 서버 + 신버전 클라이언트**: 최상위만 채워지고 하위는 예전처럼 부모를
  물려받는다. 값을 잃지는 않는다.
