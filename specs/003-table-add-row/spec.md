# Feature Specification: 표 보기 카드 추가 진입점

**Feature Branch**: `003-table-add-row`

**Created**: 2026-08-04

**Status**: Draft

**Input**: brainstorming 설계 [design.md](design.md)의 결정을 그대로 옮긴 것. 노션의 `New task` / `New sub-item`이 참조 UX다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 그룹 목록 끝에서 카드를 이어 만든다 (Priority: P1)

표를 속성으로 묶어 보는 사람은 한 그룹에 카드를 여러 개 이어 넣는다. 지금은 그룹으로 묶는 순간 목록 아래의 추가 줄이 사라지고 그룹 이름 옆의 `+`만 남는다. 카드를 하나 넣을 때마다 방금 만든 카드에서 눈과 손을 떼고 목록 맨 위로 돌아가야 한다.

이 이야기는 그룹마다 카드 목록 **끝**에 추가 줄을 놓아, 방금 만든 카드 바로 아래에서 다음 카드를 이어 만들게 한다.

**Why this priority**: 표에서 카드를 만드는 일상 동작이고, 그룹을 쓰는 사용자가 매번 겪는다. 이것만 있어도 기능이 성립한다.

**Independent Test**: 속성으로 묶인 표에서 한 그룹의 목록 끝 추가 줄을 눌러 카드가 그 그룹에 생기는지, 제목을 바로 입력할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 속성으로 묶인 표와 카드가 들어 있는 그룹, **When** 그 그룹의 목록 끝 추가 줄을 누르면, **Then** 그 그룹의 속성값이 채워진 카드가 목록 끝에 생기고 제목을 바로 입력할 수 있다
2. **Given** 카드가 하나도 없는 그룹, **When** 표를 보면, **Then** 그 그룹에도 추가 줄이 보인다
3. **Given** 접어 둔 그룹, **When** 표를 보면, **Then** 그 그룹에는 추가 줄이 보이지 않는다
4. **Given** 방금 만든 카드의 제목을 입력하고 확정한 상태, **When** 같은 추가 줄을 다시 누르면, **Then** 같은 그룹에 다음 카드가 이어서 생긴다
5. **Given** 속성으로 묶지 않은 표, **When** 표를 보면, **Then** 기존 추가 줄이 지금과 똑같이 하나만 있다
6. **Given** 속성으로 묶은 표, **When** 그룹 이름 옆의 기존 `+`를 누르면, **Then** 지금과 똑같이 동작한다

---

### User Story 2 - 하위 카드를 표에서 바로 만든다 (Priority: P2)

하위 카드를 쓰는 사람은 상위 카드 아래에 항목을 이어 붙인다. 지금 표에서는 하위 카드가 이미 있는 카드만 펼칠 수 있고, 그 목록 끝에 추가 줄이 없다. 하위 카드를 더하려면 카드 상세를 열어야 한다.

이 이야기는 펼친 하위 목록 끝에 추가 줄을 놓는다.

**Why this priority**: US1보다 쓰는 사람이 적지만, 지금은 표를 벗어나야만 되는 일을 표 안에서 끝내게 한다.

**Independent Test**: 하위 카드가 있는 카드를 펼쳐 목록 끝 추가 줄을 누르고, 하위 카드가 그 카드 아래에 생기는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 하위 카드가 하나 이상 있고 펼쳐진 카드, **When** 하위 목록 끝 추가 줄을 누르면, **Then** 그 카드의 하위 카드가 목록 끝에 생기고 제목을 바로 입력할 수 있다
2. **Given** 하위 카드가 하나도 없는 카드, **When** 표를 보면, **Then** 하위 목록도 추가 줄도 보이지 않는다
3. **Given** 하위 카드를 만든 직후, **When** 화면을 보면, **Then** 새 하위 카드가 상위 카드 아래에 들여쓰기되어 보인다

---

### User Story 3 - 하위 카드가 없는 카드에서 첫 하위 카드를 만든다 (Priority: P3)

하위 카드가 하나도 없는 카드는 펼칠 것이 없어 US2의 추가 줄이 닿지 않는다. 첫 하위 카드를 만들 진입점이 표 안에 필요하다.

이 이야기는 행의 **더 많은 행동** 메뉴에 하위 카드 추가 항목을 놓는다.

**Why this priority**: US2를 완성하는 조각이다. 없으면 "하위 카드가 있는 카드만 표에서 하위 카드를 늘릴 수 있다"는 어색한 상태로 남는다.

**Independent Test**: 하위 카드가 없는 카드의 더 많은 행동 메뉴에서 하위 카드 추가를 고르고, 그 카드가 펼쳐지며 새 하위 카드가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 하위 카드가 하나도 없는 카드, **When** 더 많은 행동 메뉴를 열면, **Then** 하위 카드 추가 항목이 있다
2. **Given** 그 항목을 고른 뒤, **When** 화면을 보면, **Then** 그 카드가 펼쳐지고 새 하위 카드가 아래에 보이며 제목을 바로 입력할 수 있다
3. **Given** 하위 카드가 이미 하나 이상 있는 카드, **When** 더 많은 행동 메뉴를 열면, **Then** 하위 카드 추가 항목이 없다 — 목록 끝 추가 줄로 만든다

---

### Edge Cases

- **하위 카드 깊이 한도에 닿은 카드**: 하위 목록 끝 추가 줄과 더 많은 행동 메뉴 항목이 **둘 다 보이지 않는다.** 눌러 놓고 거절당하는 대신 처음부터 제시하지 않는다.
- **카드를 만들 권한이 없는 사용자**: 세 진입점 어느 것도 보이지 않는다.
- **읽기 전용으로 열린 보기(공유 링크 등)**: 세 진입점 어느 것도 보이지 않는다.
- **추가 줄을 빠르게 두 번 누름**: 카드가 하나만 생긴다.
- **카드 생성이 서버에서 실패**: 사용자에게 실패를 알리고 표는 원래 상태로 남는다. 빈 행이 남지 않는다.
- **속성 접근 규칙(기능 002)이 걸린 보드에서 규칙 대상 그룹에 카드를 만든 경우**: 만든 사람이 그 속성값 카드를 볼 권한이 없으면 카드가 목록에 나타나지 않는다. 이는 기능 002의 정의된 동작이며 이 기능의 결함이 아니다.
- **다른 사람이 같은 그룹에 카드를 동시에 추가**: 두 카드가 모두 남는다. 추가 줄은 항상 목록의 끝에 있다.

## Requirements *(mandatory)*

### Functional Requirements

**그룹 카드 추가 (US1)**

- **FR-001**: 속성으로 묶인 표는 각 그룹의 카드 목록 끝에 카드 추가 줄을 제공해야 한다
- **FR-002**: 카드가 하나도 없는 그룹에도 카드 추가 줄이 보여야 한다
- **FR-003**: 접어 둔 그룹에는 카드 추가 줄이 보이지 않아야 한다
- **FR-004**: 그룹의 카드 추가 줄로 만든 카드는 그 그룹의 속성값을 가져야 한다
- **FR-005**: 속성으로 묶지 않은 표의 기존 카드 추가 줄은 지금과 동일하게 동작해야 한다
- **FR-006**: 그룹 머리글의 기존 카드 추가 수단은 지금과 동일하게 동작해야 한다

**하위 카드 추가 (US2, US3)**

- **FR-007**: 펼쳐진 하위 카드 목록의 끝에 하위 카드 추가 줄을 제공해야 한다
- **FR-008**: 하위 카드가 하나도 없는 카드는 행의 더 많은 행동 메뉴에서 하위 카드를 만들 수 있어야 한다
- **FR-009**: 하위 카드가 하나 이상 있는 카드의 더 많은 행동 메뉴에는 하위 카드 추가 항목이 없어야 한다
- **FR-010**: 더 많은 행동 메뉴로 하위 카드를 만들면 그 카드가 자동으로 펼쳐져 새 하위 카드가 보여야 한다
- **FR-011**: 하위 카드 깊이 한도에 닿은 카드는 하위 카드 추가 줄과 메뉴 항목이 모두 보이지 않아야 한다

**공통**

- **FR-012**: 어느 진입점으로 만들든 새 카드의 제목을 곧바로 입력할 수 있어야 한다
- **FR-013**: 카드를 만들 권한이 없거나 읽기 전용으로 열린 보기에서는 어느 진입점도 보이지 않아야 한다
- **FR-014**: 생성 요청이 실패하면 사용자에게 알리고, 표에 빈 행이 남지 않아야 한다
- **FR-015**: 추가 줄이나 메뉴 항목을 연달아 눌러도 카드가 한 번만 만들어져야 한다
- **FR-016**: 새 진입점의 문구는 영어와 한국어 양쪽에 제공되어야 한다

### Key Entities

- **카드**: 표의 한 행. 속성값을 갖고, 다른 카드의 하위가 될 수 있다
- **하위 카드**: 상위 카드에 속한 카드. 상위로부터의 깊이를 가지며 한도를 넘을 수 없다
- **그룹**: 표를 묶는 속성값 하나와 거기 속한 카드 목록. 접거나 펼칠 수 있다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 속성으로 묶인 표에서 카드 3개를 연달아 만들 때, 목록 맨 위로 시선이나 마우스를 되돌리는 일이 0회다
- **SC-002**: 표에서 하위 카드를 만들 때 카드 상세를 여는 일이 0회다 — 하위 카드가 이미 있든 없든
- **SC-003**: 카드를 만들 권한이 없는 사용자에게 세 진입점이 노출되는 경우가 0건이다
- **SC-004**: 깊이 한도에 닿은 카드에서 하위 카드 생성이 거부되는 경험이 0건이다 — 진입점을 미리 감추므로
- **SC-005**: 기존 표 동작(그룹 없는 보기의 추가 줄, 그룹 머리글의 추가 수단, 카드 열기·수정·삭제) 회귀 0건

## Assumptions

- 카드 생성 자체는 이미 동작한다. 이 기능은 **진입점만** 더하며 생성 규칙(속성 채움, 되돌리기, 필터 반영)은 기존 동작을 그대로 쓴다
- 하위 카드 생성 경로도 이미 있다. 카드 상세 화면이 쓰고 있으며 표에서 같은 경로를 부른다
- 하위 카드 깊이 한도 값은 기존 설정을 따르며 이 기능이 바꾸지 않는다
- 하위 카드가 없는 카드를 펼칠 수 있게 만들지 않는다. 모든 행에 펼침 표시가 생기는 변화는 이 기능이 주는 이득보다 크다 — 대신 더 많은 행동 메뉴를 진입점으로 쓴다
- 웹앱만 바뀐다. 서버 변경이 없다
- 표 외의 보기(보드, 갤러리, 캘린더)는 범위 밖이다
