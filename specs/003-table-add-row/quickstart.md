# Quickstart: 표 보기 카드 추가 진입점

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contracts**: [contracts/component-contracts.md](contracts/component-contracts.md)

이 기능이 동작하는지 확인하는 방법을 적는다. 구현 코드는 여기 넣지 않는다.

---

## 사전 준비

### 필요한 보드

| 조건 | 이유 |
|---|---|
| 표 보기 하나 | 검증 대상 |
| 속성으로 묶은(그룹) 표 보기 하나 | US1 |
| 카드가 0개인 그룹이 하나 이상 | FR-002 |
| 접을 수 있는 그룹 | FR-003 |
| 하위 카드가 1개 이상인 카드 | US2 |
| 하위 카드가 0개인 카드 | US3 |

로컬 개발 서버 좌표와 활성 팀은 개인 메모리의 "로컬 개발 환경 좌표" 항목을 따른다.

### 배포

플러그인은 빌드·배포해야 반영된다. 소스만 고치면 실행 중인 서버는 그대로다.

```bash
export MM_DEBUG=1
cd webapp && npm run debug:watch    # 켜두면 저장 시 자동 배포
```

일회성으로는 `MM_DEBUG=1 make dist-linux` 후 `./build/bin/pluginctl deploy focalboard dist/boards-<버전>.tar.gz`.

배포 후 **브라우저 하드 리프레시**가 필요하다 (HMR 없음).

## 자동 검증

```bash
make webapp-ci      # npm run check + npm run test + npm run check-types
```

**완료 판정**: baseline 대비 **신규 실패 0건**. 개수가 아니라 실패 스위트 목록을 diff 한다 — 이 저장소는 깨끗한 상태에서도 웹앱 테스트가 다수 실패한다.

```bash
# 변경 전후 비교
npm run test 2>&1 | grep -E "^FAIL" | sed -E 's/ \([0-9.]+ s\)//' | sort -u > after.txt
git stash -u -q && npm run test 2>&1 | grep -E "^FAIL" | sed -E 's/ \([0-9.]+ s\)//' | sort -u > before.txt
git stash pop -q && diff before.txt after.txt
```

타입 검사도 같은 방식으로 목록을 비교한다.

**표 스냅샷**: 추가 줄이 생기므로 갱신이 필요하다. 갱신은 변경 의도를 확인한 뒤에만 하고(constitution IV), 갱신 전후로 그 스위트의 실패 **개수**가 같은지 확인한다.

## 수동 검증 시나리오

### 시나리오 1 — 그룹 목록 끝에서 카드 잇기 (US1)

1. 속성으로 묶은 표 보기를 연다
2. 카드가 들어 있는 그룹의 목록 **끝**에 `+ 새 카드`가 있는지 본다
3. 누른다 → 카드가 그 그룹 목록 끝에 생기고 제목 칸에 커서가 있다
4. 제목을 입력하고 확정한다
5. 같은 줄을 다시 누른다 → 다음 카드가 이어서 생긴다

**통과 기준**: 3~5를 하는 동안 목록 맨 위로 올라간 적이 0회. 새 카드의 그룹 속성값이 그 그룹 값과 같다.

### 시나리오 2 — 빈 그룹과 접힌 그룹 (FR-002, FR-003)

1. 카드가 0개인 그룹을 본다 → `+ 새 카드`가 있다
2. 눌러 카드를 만든다 → 그 그룹에 생긴다
3. 그룹을 접는다 → 카드 행도 추가 줄도 보이지 않는다

### 시나리오 3 — 하위 목록 끝에서 하위 카드 만들기 (US2)

1. 하위 카드가 1개 이상인 카드를 펼친다
2. 하위 목록 **끝**에 `+ 새 하위 카드`가 있는지 본다 (들여쓰기되어 있다)
3. 누른다 → 하위 카드가 목록 끝에 생기고 제목 칸에 커서가 있다

**통과 기준**: 카드 상세 팝업이 열리지 않는다.

### 시나리오 4 — 하위 카드가 없는 카드 (US3)

1. 하위 카드가 0개인 카드의 ⋯ 메뉴를 연다 → `하위 카드 추가`가 있다
2. 고른다 → 그 카드가 **저절로 펼쳐지고** 새 하위 카드가 아래에 보인다. 제목 칸에 커서가 있다
3. 같은 카드의 ⋯ 메뉴를 다시 연다 → `하위 카드 추가`가 **없다** (이제 목록 끝 추가 줄로 만든다)

### 시나리오 5 — 깊이 한도 (FR-011)

1. 하위 카드를 한도(5)까지 중첩해 만든다
2. 마지막 깊이의 카드를 본다 → 하위 추가 줄이 없고 ⋯ 메뉴에도 항목이 없다

**통과 기준**: 생성이 거부되는 경험이 0회. 진입점이 애초에 보이지 않는다.

### 시나리오 6 — 권한과 읽기 전용 (FR-013)

1. 카드를 만들 권한이 없는 계정으로 같은 보드를 연다 → 세 진입점 어느 것도 없다
2. 공유 링크(읽기 전용)로 보드를 연다 → 세 진입점 어느 것도 없다

## 회귀 확인

이 기능이 건드리지 않기로 한 것들이 그대로인지 본다.

| 대상 | 확인 |
|---|---|
| 그룹 없는 표의 기존 `+ New` | 위치·문구·동작이 그대로 |
| 그룹 머리글의 `+` | 그대로 동작 |
| 다른 보기(보드·갤러리·캘린더)의 ⋯ 메뉴 | `하위 카드 추가` 항목이 **없다** |
| 카드 상세의 하위 카드 섹션 | 그대로 동작 (만든 뒤 카드를 연다) |
| 카드 열기·수정·삭제·복제 | 그대로 |
