## 1. 속성 추가와 값 입력 (P1)

**목표**: FR-001~006

1. 보드에서 속성 추가 → 종류 목록에 **본부**와 **부서**가 있다
2. 본부 속성을 추가하고 카드에서 값을 연다 → 조직 관리의 활성 본부만 나온다
3. 값을 둘 이상 고른다 → 모두 저장되고 함께 표시된다
4. 표·보드 보기에서 그 카드를 본다 → 조직 **이름**이 보인다 (ID가 아니라)

**무효 참조 확인**: DB에서 부서 하나를 비활성으로 바꾼 뒤 그 값을 가진 카드를
연다. 값이 사라지지 않고 문제 있는 값으로 표시되면 통과 (FR-006).

```sql
UPDATE orgunits SET active = false WHERE id = '<부서 ID>';
-- 확인 후 되돌린다
UPDATE orgunits SET active = true  WHERE id = '<부서 ID>';
```

## 2. 본부로 부서 좁히기 (P2)

**목표**: FR-007~010, FR-016~017

| 카드 상태 | 부서 선택지 | 요구사항 |
|---|---|---|
| 본부 = 생산 | 생산본부 부서만 | FR-007 |
| 본부 = 비어 있음 | 전체 활성 부서 | FR-008 |
| 본부 = 생산, 관리 | 두 본부의 부서 모두 | FR-009 |
| 본부 속성 둘, 각각 생산·연구 | 두 본부의 부서 모두 | FR-010 |

**자동 비우기**: 본부=관리·부서=재경전산팀인 카드에서 본부를 생산으로 바꾼다.
부서가 비워지면 통과 (FR-016).

**되돌리기**: 위 직후 `Ctrl+Z` **한 번**으로 본부와 부서가 함께 원래대로
돌아가면 통과 (FR-017). 두 번 눌러야 하면 실패다.

## 3. 조직으로 담당자 좁히기 (P3)

**목표**: FR-011~015, FR-018

| 카드 상태 | 담당자 선택지 | 요구사항 |
|---|---|---|
| 본부=생산, 부서 비어 있음 | 생산본부 + 하위 부서 소속 | FR-012 |
| 본부=생산, 부서=생산팀 | 생산팀 소속만 | FR-011 |
| 본부·부서 모두 비어 있음 | 전체 (좁히지 않음) | FR-013 |

**조직 없는 사용자**: 시스템관리자 계정처럼 소속이 없는 사용자가 조직 지정된
카드의 선택지에 **나오지 않으면** 통과 (FR-014).

**이미 있는 값 유지**: 위 상태에서 그 관리자를 미리 담당자로 넣어 둔 뒤 선택지를
연다. 목록에 남아 있으면 통과 (FR-015).

**담당자 보존**: 본부=관리·담당자=재경전산팀원인 카드에서 본부를 생산으로 바꾼다.
담당자가 그대로면 통과 (FR-018).

## 4. 필터·그룹화·내보내기 (P4)

**목표**: FR-019~021

1. 뷰 필터에서 본부 속성을 고른다 → 조직 관리의 본부가 선택지로 나온다 (FR-019)
2. `본부 = 생산`으로 거른다 → 그 값을 가진 카드만 남는다
3. Group by를 본부로 바꾼다 → 본부별로 묶인다 (FR-020)
4. 값이 여러 개인 카드가 해당 그룹마다 나타난다
5. CSV로 내보낸다 → 조직 **이름**이 찍힌다 (FR-021)

## 5. 회귀 확인 (FR-022, FR-023)

**적용 범위**: 담당자 좁히기가 카드 팝업·표 셀·보드 보기 **세 곳 모두**에서 같게
동작하는지 확인한다 (FR-022). 한 곳만 좁혀지면 실패다.

**기존 보드 무영향**: 본부·부서 속성이 없는 보드를 연다. 카드 조회·편집 동작이
이전과 같으면 통과 (FR-023). 특히 담당자 선택지가 좁혀지지 않아야 한다.

## 6. 품질 게이트

constitution 원칙 I. 변경이 닿은 패키지만 실행한다.

```bash
make webapp-ci     # webapp 변경
make server-lint   # server 변경
make server-test   # server 변경 — CI 미집행이라 로컬 필수
```

**판정은 실패 개수가 아니라 실패 스위트 목록의 diff로 한다.** 이 저장소는 깨끗한
상태에서도 실패가 있다 — `server/app` 7건 + `server/model` 1건, webapp 114개 스위트.
`TestPatchBoard`는 비동기 알림 타이밍 때문에 간헐 실패하므로 회귀로 오판하지
않는다.

기준선을 잴 때는 `git stash -u`로 **미추적 파일까지** 치운다. 새로 만든 테스트
파일이 남아 있으면 기준선이 오염된다.
