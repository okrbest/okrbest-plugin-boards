# 종단 검증: 카드 접근 권한을 역할 매트릭스로 정한다

배포한 플러그인에서 실제 계정으로 훑는다. 게이트만으로는 부족하다 — 이 저장소의 결함은
화면을 조작해야 드러난다 (원칙 I).

## 준비

권한 판정은 **보는 사람이 누구냐**로 갈리므로 계정이 여럿 필요하다. 조직 배정은 메인
서버가 소유하니 배정부터 확인한다.

로컬 개발 환경(팀 `한국케이밸브`)에 이미 배정된 계정을 쓴다. **비밀번호는 공통
`kkv1234!!`다.**

| 계정 | 이메일 | 본부 | 부서 | 직책 |
|---|---|---|---|---|
| A | `sungmin.ahn@kkv.co.kr` | 대표 | — | CEO |
| B | `myoungeon.lee@kkv.co.kr` | CSO - 영업 | — | CSO |
| C | `minsu.kwon@kkv.co.kr` | COO - 생산 | — | COO |
| D | `kisun.kim@kkv.co.kr` | — | 영업1팀 | 팀장 |
| E | `jiho.moon@kkv.co.kr` | — | 영업1팀 | 팀원 |
| F | `daechan.lee@kkv.co.kr` | — | 영업2팀 | 팀원 |
| G | (팀 관리자 계정) | — | — | — |
| H | (보드 관리자만, 팀 관리자 아님) | — | — | — |

D·E는 같은 부서, F는 다른 부서다. B·C는 서로 다른 본부라 "본인 본부 / 타 본부"가 한
쌍으로 확인된다.

배정을 바꿔야 하면 메인 서버에서 한다. **이 플러그인은 배정을 못 바꾼다.**

배정은 이렇게 확인한다.

```bash
docker exec -e PGPASSWORD='<postgres 비밀번호>' mattermost-postgres \
  psql -U mmuser -d mattermost_test -t -A -F'|' -c "
SELECT pd.name, u.email, ou.name
FROM userorgprofiles p JOIN users u ON u.id=p.userid
JOIN positiondefinitions pd ON pd.id=p.primarydutyid
LEFT JOIN orgunits ou ON ou.id=p.primaryorgunitid
ORDER BY pd.rank, ou.name;"
```

플러그인 API(`/teams/{teamID}/org-profiles`)는 직책을 안 내려준다 — 조직 정보를 최소한만
내보내려고 일부러 뺐다. 그래서 확인은 DB로 한다.

G·H는 6절에서만 쓴다. 묶음 편집 권한이 갈리는지 보려면 둘이 필요하다.

## 빌드·배포

webapp만 바뀌면 서버 빌드를 건너뛴다.

```bash
cd webapp && npm run debug
cd .. && make deploy-from-watch
```

서버가 바뀌면 Go 바이너리까지 올린다.

```bash
MM_DEBUG=1 make server-linux
make deploy-from-watch
```

배포 뒤 번들에 새 코드가 들어갔는지 확인한다. 소스만 고치면 반영되지 않는다.

## 1절 — 묶음을 팀에 만든다 (US2)

1. 보드를 새로 만들고 OKR Board로 쓰기를 켠다
2. 카드 접근 권한을 켠다
3. **팀에 묶음이 없으므로** "묶음부터 정하세요"가 뜬다
4. 직책 묶음 넷을 만든다 — 대표 / C-Level(CSO·COO·CFO·CGO) / 팀장 / 팀원

**확인**

- [ ] 직책 목록이 조직 마스터에서 온다. 손으로 입력하는 칸이 없다
- [ ] 한 묶음에 직책 넷이 들어간다
- [ ] 어느 묶음에도 안 든 직책이 목록으로 보인다 (FR-023)
- [ ] 묶음 옆에 "이 팀의 모든 보드에 적용됩니다"가 있다 (FR-011a)

## 2절 — 표준 여섯 줄이 깔린다 (US3)

**확인**

- [ ] 카드 접근 권한을 켠 직후 표가 이미 채워져 있다 (FR-019)
- [ ] 표의 12칸이 요구사항 이미지와 같은 자리에 같은 값으로 있다 (SC-001)
- [ ] `규칙으로 보기`를 열면 줄이 **여섯 개**다 — 4번 한 줄이 팀장·팀원 두 묶음을 가리킨다

## 3절 — 둘째 보드는 스위치 1회다 (SC-004) 🎯

1. **같은 팀에** 보드를 하나 더 만들고 OKR Board로 쓰기를 켠다
2. 카드 접근 권한을 켠다

**확인**

- [ ] 묶음을 다시 배정하지 않는다 — 팀에 이미 있다
- [ ] 표가 표준 여섯 줄로 이미 채워져 있다
- [ ] 켜는 조작이 **스위치 1회**로 끝난다 (SC-004)

## 4절 — 매트릭스대로 판정된다 (US1) 🎯

카드를 여섯 장 만든다. 유형과 본부·부서를 다르게 준다.

| 카드 | 유형 | 본부 | 부서 | 담당자 |
|---|---|---|---|---|
| ① | Objective | 영업본부 | — | — |
| ② | Objective | 개발본부 | — | — |
| ③ | Key Result | 영업본부 | — | — |
| ④ | Tasks | 영업본부 | 영업1팀 | E |
| ⑤ | Tasks | 영업본부 | 영업1팀 | D |
| ⑥ | Tasks | 영업본부 | 영업2팀 | F |

계정을 바꿔가며 확인한다. **각 칸이 매트릭스의 한 칸이다.**

| 보는 사람 | 카드 | 기대 | 근거 |
|---|---|---|---|
| A 대표 | ①②③④⑤⑥ | 전부 편집 | 규칙 1 |
| B CSO(영업) | ① | 편집 | 규칙 2 |
| B CSO(영업) | ② | **댓글만** — 편집 막힘 | 규칙 3 |
| C COO(개발) | ① | **댓글만** | 규칙 3 |
| C COO(개발) | ② | 편집 | 규칙 2 |
| D 팀장(영업1팀) | ①③ | 조회만 | 규칙 4 |
| D 팀장(영업1팀) | ② | **안 보임** | 빈칸 (FR-009) |
| D 팀장(영업1팀) | ④⑤ | 편집 | 규칙 5 |
| D 팀장(영업1팀) | ⑥ | **안 보임** | 다른 부서 |
| E 팀원(영업1팀) | ①③ | 조회만 | 규칙 4 |
| E 팀원(영업1팀) | ② | **안 보임** | 빈칸 |
| E 팀원(영업1팀) | ④ | 편집 | 규칙 6 — 담당자가 나 |
| E 팀원(영업1팀) | ⑤ | **안 보임** | 남의 과제 |

**가장 깨지기 쉬운 두 자리**

- **D·E가 ②를 못 보는가.** 이게 지금 안 되던 것이다. 조회로 새어 나오면 게이트 계산이
  틀린 것이다 (research R2)
- **E가 ④를 편집하는가.** 팀장 D가 만들어 E에게 배정한 카드다. 작성자가 아닌데 담당자로
  통과해야 한다

## 5절 — 값이 없을 때 (엣지)

1. 본부 값이 빈 Objective 카드를 만든다
2. B(영업 CSO)로 본다

**확인**

- [ ] `sameDivision`도 `otherDivision`도 성립하지 않아 접근 없음 — 타 본부로 새지 않는다
- [ ] 조직 배정이 없는 계정으로 보면 아무 관계도 성립하지 않는다

## 6절 — 묶음은 팀 관리자만 고친다 (US2)

1. **H(보드 관리자, 팀 관리자 아님)**로 보드 공유 대화상자를 연다
2. **G(팀 관리자)**로 같은 화면을 연다

**확인**

- [ ] H에게 묶음이 **보인다** — `C-Level`이 누구인지 확인할 수 있다 (FR-011c)
- [ ] H는 묶음을 **못 고친다**. 잠긴 상태로 보인다 (FR-011b)
- [ ] H는 매트릭스 칸은 고칠 수 있다 — 규칙은 보드 것이다
- [ ] G는 묶음을 고칠 수 있다
- [ ] G가 C-Level에 직책을 하나 더하면, **다른 보드의 판정이 함께 바뀐다** (SC-006)

마지막 줄을 반드시 두 보드에서 확인한다. 팀 저장의 값과 위험이 동시에 여기 있다.

## 7절 — 손으로 만든 예외가 살아남는가 (US3)

1. `규칙으로 보기`에서 줄을 하나 더한다 — 예: 특정 부서만 편집
2. 표로 돌아와 칸 하나를 고친다
3. 저장한다

**확인**

- [ ] 손으로 만든 줄이 그대로 있다 (FR-021)
- [ ] 표가 그 줄을 "표 밖" 으로 알려준다
- [ ] 고친 칸에 대응하는 줄만 바뀌었다

## 8절 — 기존 보드가 안 바뀐다 (SC-005)

**켜기 전에 판정 결과를 적어 둔다.** 배포 뒤 같은 카드를 같은 계정으로 다시 본다.

1. 절대값 규칙을 쓰는 기존 보드를 고른다
2. 계정 셋으로 카드 다섯 장의 권한을 적는다 (배포 전)
3. 배포한다
4. 같은 15칸을 다시 본다

**확인**

- [ ] 15칸이 전부 같다 (SC-005 — 변화 0건)
- [ ] 규칙 목록의 저장 형식이 안 바뀌었다. 보드를 열었다는 이유로 `dutyId`가
      `tierIds`로 옮겨가지 않는다 (FR-016)

## 9절 — 조직이 늘어도 규칙이 안 는다 (SC-003)

1. 메인 서버에서 본부를 하나 더 만든다
2. 그 본부 소속 계정으로 본다

**확인**

- [ ] 규칙을 하나도 안 고쳤는데 새 본부에 매트릭스가 그대로 걸린다
- [ ] 규칙 줄 수가 그대로다 (0줄 증가)

## 10절 — 005·006·007·008 회귀

- [ ] 조직 속성으로 거르기·묶기가 그대로다 (005)
- [ ] 직책 속성이 그대로다 (006)
- [ ] 조직 값 색이 그대로다 (007)
- [ ] OKR 사다리와 표 보기 펼침이 그대로다 (008)
- [ ] 실보드를 **읽기만** 해서 카드 수와 규칙이 그대로인지 확인한다
