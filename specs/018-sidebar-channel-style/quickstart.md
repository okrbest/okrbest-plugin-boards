# Quickstart: 배포·실측 검증

**Spec**: [spec.md](../spec.md) | **Contracts**: [contracts/ui-surfaces.md](contracts/ui-surfaces.md)

화면 동작이 바뀌는 변경이므로 게이트 통과만으로 완료 선언할 수 없다(constitution I). 아래 실측을 근거로 제시한다.

## 전제

- 로컬 Mattermost(docker postgres)와 활성 팀 `kkv`. 검증은 **배포된 플러그인 기준**으로만 한다.
- `npm run debug:watch`가 저장 → 자동 배포(약 11초). 소스만 고치고 배포하지 않으면 반영되지 않는다.
- 브라우저 확인은 playwright MCP를 먼저 쓴다.

## 게이트 (변경이 webapp에만 닿음)

```bash
cd webapp
npm run check        # eslint + stylelint
npm run test         # Jest — 실패 스위트 목록을 baseline과 diff로 판정
npm run check-types  # tsc
```

`make webapp-ci`는 baseline에서도 exit=2이므로 세 단계를 따로 돌려 목록으로 대조한다.

## 실측 시나리오

채널 사이드바와 보드 사이드바를 같은 화면에서 비교할 수 있도록 Boards를 채널 안이 아닌 전체 화면으로 연다.

### 1. 토글 (US1)

1. 데스크톱 폭에서 보드 열기 → 사이드바 상단에 dock 토글이 보인다 (U-01).
2. 클릭 → 사이드바가 접히고 본문이 넓어지며 보이기 버튼이 남는다 (U-02).
3. 새로고침 → 여전히 숨김 (U-04, SC-002).
4. 보이기 클릭 → 복원, 다시 새로고침해도 보임 (U-03).
5. 창 폭을 768px 미만으로 줄였다 넓히기 → 저장된 선택이 유지된다 (U-06·07).
6. 다른 계정(비관리자 QA 계정)으로 로그인 → 이전 계정의 숨김 상태에 영향받지 않는다 (spec 수용 시나리오 4). 사이드바 버그는 비관리자로 재현되는 전례가 있으므로 이 단계는 생략하지 않는다.

### 2. 시각 대조 (US2)

채널 목록과 보드 목록을 나란히 두고 다섯 항목을 대조한다 (SC-003):

| 항목 | 기대 |
|---|---|
| 활성 항목 | 두 영역 모두 완전 반전, 좌측 세로선 없음 |
| hover | 같은 배경 하이라이트 |
| 카테고리 헤더 | 12px/600/uppercase/자간 동일 |
| 항목 크기 | 15px 글자, 32px 행 |
| 폭 | 창 폭을 늘리고 줄일 때 같은 clamp 규칙으로 반응 |

테마를 어두운 테마로 바꿔 같은 다섯 항목을 한 번 더 확인한다(변수 참조 검증).

### 3. 회귀 (FR-010)

- 카테고리 접기/펼치기, 보드 드래그 정렬, 보드 ⋯ 메뉴(가변 폭에서 위치 확인 — U-12·V-05), 숨긴 보드 되찾기 행(016) 동작 확인.
- 창 폭 최소(180px)·최대(440px)에서 긴 보드 이름 말줄임 확인.

## 완료 기준

게이트 3단계 출력 + 위 시나리오 결과(스크린샷 포함)를 제시한 뒤에만 완료를 선언한다.
