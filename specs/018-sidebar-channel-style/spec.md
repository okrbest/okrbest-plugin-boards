**Feature Branch**: `018-sidebar-channel-style`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사이드바를 숨기고 되살린다 (Priority: P1)

보드를 넓게 보고 싶은 사용자가 사이드바 상단의 숨기기 버튼을 눌러 보드 목록 영역을 접는다. 본문이 그만큼 넓어진다. 다시 목록이 필요하면 화면에 남은 보이기 버튼을 눌러 사이드바를 되살린다. 숨겨 둔 채 새로고침하거나 나중에 다시 들어와도 숨긴 상태가 그대로다.

**Why this priority**: 지금은 데스크톱에서 사이드바를 접을 방법이 없다. 채널 영역에는 이미 같은 토글이 있어, 보드에만 없는 기능이 사용자에게 일관성 결핍으로 보인다. 새 기능 가치가 가장 크다.

**Independent Test**: 시각 변경 없이 토글만 구현해도 성립한다. 숨기기 → 본문 확장 → 보이기 → 새로고침 후 상태 유지, 네 단계를 눌러보는 것만으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 데스크톱 폭에서 사이드바가 보이는 상태, **When** 숨기기 버튼을 누르면, **Then** 사이드바가 사라지고 보드 본문이 그 폭을 차지하며 보이기 버튼이 나타난다.
2. **Given** 사이드바를 숨긴 상태, **When** 보이기 버튼을 누르면, **Then** 사이드바가 원래 폭으로 돌아온다.
3. **Given** 사이드바를 숨긴 상태, **When** 페이지를 새로고침하거나 다른 보드로 이동하면, **Then** 사이드바는 여전히 숨겨져 있다.
4. **Given** 같은 브라우저에 다른 사용자가 로그인, **When** 보드 화면을 열면, **Then** 이전 사용자의 숨김 상태에 영향받지 않는다.

---

### User Story 2 - 보드 목록이 채널 목록과 같은 시각 언어를 쓴다 (Priority: P2)

채널 목록과 보드 목록을 오가는 사용자가 두 영역에서 같은 시각 규칙을 본다. 지금 보고 있는 보드는 채널처럼 완전 반전(어두운 배경에 밝은 글자)으로 표시되고, 마우스를 올린 항목은 같은 배경 하이라이트를 받는다. 카테고리 헤더·글자 크기·사이드바 폭 규칙도 채널 목록과 같다.

**Why this priority**: 기능이 아니라 일관성 개선이다. 토글 없이도 적용할 수 있고, 토글만 있어도 제품은 성립하므로 P2.

**Independent Test**: 채널 목록과 보드 목록을 나란히 띄워 활성 항목·hover·헤더·폭의 시각 요소를 항목별로 대조하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 어떤 보드를 보고 있는 상태, **When** 사이드바에서 그 보드 항목을 확인하면, **Then** 채널 목록의 활성 채널과 같은 완전 반전 스타일로 표시된다 (기존의 좌측 세로선 + 옅은 배경 방식은 쓰지 않는다).
2. **Given** 사이드바의 임의 항목, **When** 마우스를 올리면, **Then** 채널 목록 항목과 같은 배경 하이라이트가 나타난다.
3. **Given** 채널 목록과 보드 목록을 나란히 비교, **When** 카테고리 헤더·항목 글자 크기·행 높이를 대조하면, **Then** 두 영역의 값이 일치한다.
4. **Given** 창 폭을 바꾸는 상황, **When** 화면이 넓어지거나 좁아지면, **Then** 보드 사이드바 폭이 채널 사이드바와 같은 최소·최대 규칙으로 늘고 준다.

---

### Edge Cases

- 사이드바를 숨긴 채 창 폭을 모바일 폭까지 좁혔다가 다시 넓히면? — 사용자가 직접 숨긴 상태가 우선이다. 자동 숨김/해제가 저장된 선택을 덮어쓰지 않는다.
- 브라우저가 상태 저장을 허용하지 않으면(시크릿 모드, 저장소 차단)? — 토글은 그 세션 안에서는 동작하되, 보존만 안 된다. 기본값은 "보임"이다.
- 접근한 적 없는 새 기기·브라우저에서는? — 기본값 "보임"으로 시작한다.
- 숨긴 상태에서 다른 경로로 보드가 열리면(채널 링크, 검색 등)? — 숨김 상태를 유지한 채 본문만 그 보드로 바뀐다. 보이기 버튼은 계속 접근 가능하다.
- 기존 기능과의 충돌? — 카테고리 접기/펼치기, 보드 드래그 정렬, 숨긴 보드 되찾기(016) 등 사이드바 안의 기존 기능은 시각 변경 후에도 그대로 동작해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**숨기기/보이기 토글**

- **FR-001**: 데스크톱 폭에서 사이드바 상단에 숨기기 버튼을 제공해야 한다. 버튼 모양과 위치 문법은 채널 사이드바 토글과 같은 계열이어야 한다.
- **FR-002**: 숨긴 상태에서는 보이기 버튼이 화면에 남아 한 번의 클릭으로 사이드바를 되살릴 수 있어야 한다.
- **FR-003**: 숨김/보임 선택은 사용자별로 보존되어 새로고침·재방문 후에도 유지되어야 한다. 같은 브라우저의 다른 사용자에게는 적용되지 않는다.
- **FR-004**: 좁은 화면에서의 기존 자동 숨김 동작은 유지하되, 자동 숨김이 사용자의 저장된 선택을 덮어쓰지 않아야 한다.
- **FR-005**: 토글 버튼의 라벨(툴팁·접근성 이름)은 한국어·영어 번역을 모두 제공해야 한다.

**채널 리스트와의 시각 통일**

- **FR-006**: 현재 보고 있는 보드 항목은 채널 목록의 활성 채널과 같은 완전 반전 스타일로 표시해야 한다. 기존의 좌측 세로선 + 옅은 배경 방식은 제거한다.
- **FR-007**: 항목 hover 배경은 채널 목록과 같은 색 규칙을 써야 한다.
- **FR-008**: 항목 글자 크기·행 높이, 카테고리 헤더의 크기·굵기·자간은 채널 목록과 같아야 한다.
- **FR-009**: 사이드바 폭은 고정값 대신 채널 사이드바와 같은 최소·최대 가변 규칙을 따라야 한다.
- **FR-010**: 시각 변경 후에도 사이드바의 기존 기능 — 카테고리 접기/펼치기, 드래그 정렬, 보드 메뉴, 숨긴 보드 되찾기 행(016) — 은 동일하게 동작해야 한다.

### Key Entities

- **사이드바 표시 상태**: 사용자가 사이드바를 숨겼는지 여부. 사용자 단위로 구분되고 기기·브라우저 안에서 보존된다. 서버에 동기화하지 않는다(채널 사이드바 토글과 같은 보존 수준).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 클릭 한 번으로 사이드바를 숨기고, 클릭 한 번으로 되살릴 수 있다.
- **SC-002**: 숨긴 상태로 새로고침·재방문했을 때 100% 숨김 상태가 유지된다 (저장소가 차단된 환경 제외).
- **SC-003**: 채널 목록과 보드 목록을 나란히 대조했을 때 활성 항목·hover·카테고리 헤더·항목 크기·폭 규칙 다섯 항목이 모두 일치한다.
- **SC-004**: 기존 사이드바 기능(카테고리 접기/펼치기, 드래그 정렬, 숨긴 보드 되찾기)의 동작이 변경 전과 동일하다 — 기존 자동 테스트가 전부 통과하고 수동 점검에서 차이가 없다.

## Assumptions

- 기준 디자인은 메인 서버(okrbest 포크)의 채널 사이드바, 특히 spec 014로 적용된 시각층(완전 반전 활성 항목, 가변 폭)이다. upstream Mattermost 기본 디자인이 아니다.
- 채널 사이드바의 "레일 hover 미리보기(peek)"는 범위에서 제외한다. 보드 영역에는 호버할 레일이 없다.
- 표시 상태의 보존 수준은 채널 사이드바 토글과 동일하게 기기·브라우저별이다. 서버 저장(모든 기기 동기화)은 요구하지 않는다.
- 플러그인 모드(Mattermost 안의 Boards)가 대상이다. standalone 모드의 기존 동작은 바꾸지 않는다.
- 색·크기 값은 채널 사이드바가 쓰는 테마 변수를 그대로 참조할 수 있다고 가정한다. 보드 테마에 빠진 변수가 있으면 매핑을 추가한다.
