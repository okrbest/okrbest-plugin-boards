# 데이터 모델: 직책 속성

**Feature**: `006-org-duty-property`

새 저장소도, 새 테이블도, 새 마이그레이션도 없다. 이 문서는 **이미 있는 두 저장 공간이
직책을 어떻게 담는가**를 적는다.

---

## 1. 카드의 직책 값

기존 블록 JSON에 들어간다. 본부·부서와 똑같은 형태다.

```jsonc
// focalboard_blocks.fields
{
  "properties": {
    "<속성 템플릿 ID>": ["<직책 ID>", "<직책 ID>"]
  }
}
```

| 규칙 | 값 |
|---|---|
| 형태 | 문자열 배열 |
| 원소 | 직책 ID (26자) |
| 순서 | 사용자가 고른 순서를 유지한다 |
| 빈 값 | 키가 없거나 빈 배열 |
| 중복 | 없다 — 같은 직책을 두 번 고를 수 없다 |
| 검증 | **서버는 하지 않는다.** 값은 자유 형식 JSON이고, 유효성은 화면이 표시할 때 판단한다 |

속성 템플릿(`board.card_properties`)에는 `options` 배열이 비어 있다. 선택지가 보드가
아니라 조직 마스터에 살기 때문이다. 이 빈 `options`가 접근 규칙에서 직책을 자동으로
빼는 장치이기도 하다(FR-011).

---

## 2. 직책 (읽기 전용)

메인 서버의 `PositionDefinitions` 테이블에서 온다. 이 플러그인은 읽기만 한다.

| 필드 | 쓰임 |
|---|---|
| `id` | 카드에 저장되는 값 |
| `name` | 화면·필터·묶기·내보내기에 보이는 이름 |
| `rank` | 서버가 정렬에 쓴다. 화면은 순서를 그대로 받는다 |
| `code` | 이 기능에서 쓰지 않는다 |
| `fullVisibility` | 접근 판정용. 이 기능에서 쓰지 않는다 |

**직위는 오지 않는다.** 서버가 `kind='duty'`만, 그중 활성만 골라 서열 순으로 보낸다
(`GetDutiesForTeam`). 화면은 받은 것을 거르지 않는다 — 거르는 규칙이 두 곳에 생기면
갈라진다.

화면 도착 경로는 이미 깔려 있다: 팀 진입 시 `fetchOrgMaster`가 조직 단위·직책·소속을
한 번에 받아 `orgMaster` 슬라이스의 `dutiesByTeamId`에 넣는다. 이 기능이 추가하는
왕복은 **0회**다.

---

## 3. 이름 해석 (파생)

카드는 ID를 저장하고 화면은 이름을 보여준다. 그 사이를 잇는 조회 맵을 셀렉터 하나로
모은다(research R2).

```
getOrgLabels(teamId) → {id, name}[]     // 본부 + 부서 + 직책
```

| 소비자 | 지금 | 이후 |
|---|---|---|
| 묶기 (`centerPanel`) | 조직 단위 맵 | 합친 맵 |
| 내보내기 (`csvExporter`) | 조직 단위 맵 | 합친 맵 |
| 에디터의 사라진 값 | 넘겨받은 목록 | 그대로 (에디터는 자기 종류만 안다) |

합쳐도 안전한 이유는 ID 공간이 겹치지 않아서다. 조직 단위 ID와 직책 ID는 서로 다른
테이블에서 발급되고 26자 난수라 충돌하지 않는다.

---

## 4. 사라진 값

조직 관리에서 직책을 지워도 카드의 값은 그대로 남는다(FR-006). 마스터는 메인 서버
소유이므로, 카드의 기록이 틀렸다고 판단할 위치에 이 플러그인은 없다.

| 자리 | 사라진 직책을 어떻게 보여주나 |
|---|---|
| 카드 편집기 | 이름 자리에 `<ID> (removed)`, 라벨 색은 경고색 |
| 선택 목록 | 이미 카드에 있는 값은 목록에 남는다 — 지우려면 보여야 한다 |
| 묶기 | 이름 대신 ID |
| 내보내기 | 이름 대신 ID |

셋 다 본부·부서가 이미 하는 방식이다. 직책이 다르게 굴면 그게 버그다.

---

## 5. 하위 호환

- **기존 보드**: 직책 속성이 없으므로 아무것도 바뀌지 않는다.
- **직책 속성을 만들었다가 유형을 바꾸면**: 다른 속성 유형 변경과 같다. 값은 새 유형이
  읽지 못하는 형태로 남는다. 이 기능이 따로 처리하지 않는다.
- **구버전 클라이언트**: `orgDuty`를 모르는 클라이언트는 `unknown` 속성으로 떨어뜨린다
  (레지스트리 기본 동작). 값은 건드리지 않으므로 신버전에서 다시 열면 그대로다.
