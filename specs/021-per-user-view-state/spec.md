# Feature Specification: 표 뷰 개인 화면 제어 분리

**Feature Branch**: `021-per-user-view-state`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "표 뷰의 개인 화면 제어를 사용자별로 분리한다. 현재 표 뷰의 그룹 펼치기/접기(collapsedOptionIds)와 열 너비 조절(columnWidths)은 공유 뷰 블록(BoardView)에 저장되어 서버 patch → websocket 방송을 거쳐 같은 보드를 보는 모든 사용자의 화면에 동기화된다. 데이터 입력은 동기화되어야 하지만 개인 화면 제어는 각자의 화면에만 적용되어야 한다. 범위: (1) 표 그룹 펼치기/접기와 (2) 표 열 너비 조절을 사용자별 로컬 상태로 전환해 다른 사용자에게 전파되지 않게 한다. 읽기 전용 사용자도 자기 화면에서 그룹 접기·열 너비 조절이 가능해져야 한다. 반면 그룹(열) 숨기기/보이기(hiddenOptionIds·visibleOptionIds), 정렬·필터·표시 속성·계산식은 의도된 공유 뷰 구성이므로 기존 동작을 유지한다."

## 배경

같은 표 뷰를 여러 사용자가 동시에 볼 때, 한 사용자가 그룹을 접거나 열 너비를 바꾸면 그 변경이 서버에 저장되고 같은 보드를 보는 모든 사용자의 화면이 함께 바뀐다. 카드 내용 같은 데이터 입력은 실시간으로 동기화되는 것이 맞지만, 그룹 접힘과 열 너비는 각자 화면을 보기 좋게 조정하는 개인 화면 제어이므로 다른 사용자에게 전파되면 안 된다. 또한 현재 구조에서는 이 조작이 서버 쓰기이기 때문에 읽기 전용 사용자는 자기 화면에서조차 그룹을 접을 수 없다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 그룹 펼치기/접기는 내 화면에만 적용된다 (Priority: P1)

두 사용자가 같은 표 뷰를 보고 있다. 사용자 A가 특정 그룹을 접어도 사용자 B의 화면은 그대로다. A가 보드를 떠났다가 돌아와도 자신이 접어 둔 상태가 유지된다.

**Why this priority**: 신고된 오작동의 핵심이다. 협업 중 다른 사람의 화면이 예고 없이 바뀌는 혼란을 직접 일으킨다.

**Independent Test**: 두 브라우저(서로 다른 계정)로 같은 표 뷰를 열고, 한쪽에서 그룹을 접은 뒤 다른 쪽 화면이 바뀌지 않음을 확인한다. 이 스토리만 구현해도 가장 큰 혼란이 사라지므로 단독으로 가치가 있다.

**Acceptance Scenarios**:

1. **Given** 사용자 A와 B가 같은 표 뷰를 보고 있고 그룹 G가 펼쳐진 상태일 때, **When** A가 G의 접기 버튼을 누르면, **Then** A의 화면에서만 G가 접히고 B의 화면에서는 G가 펼쳐진 채 유지된다.
2. **Given** A가 그룹 G를 접어 둔 상태일 때, **When** A가 다른 보드로 이동했다가 같은 표 뷰로 돌아오면, **Then** G는 여전히 접혀 있다.
3. **Given** A가 그룹 G를 접어 둔 상태일 때, **When** B가 G에 속한 카드의 내용을 수정하면, **Then** 카드 내용 변경은 A에게 실시간 반영되고 G의 접힘 상태는 그대로 유지된다.

---

### User Story 2 - 열 너비 조절은 내 화면에만 적용된다 (Priority: P2)

사용자 A가 표의 열 너비를 드래그로 조절해도 사용자 B의 화면 열 너비는 바뀌지 않는다. A가 조절한 너비는 재방문 시에도 유지된다.

**Why this priority**: 접기와 같은 부류의 오작동이지만, 변화가 비교적 덜 파괴적이어서(화면 구조가 뒤바뀌지는 않음) P1보다 한 단계 낮다.

**Independent Test**: 두 브라우저로 같은 표 뷰를 열고, 한쪽에서 열 너비를 조절한 뒤 다른 쪽 화면이 바뀌지 않음을 확인한다.

**Acceptance Scenarios**:

1. **Given** A와 B가 같은 표 뷰를 보고 있을 때, **When** A가 특정 열의 너비를 조절하면, **Then** A의 화면에서만 너비가 바뀌고 B의 화면은 그대로다.
2. **Given** A가 열 너비를 조절해 둔 상태일 때, **When** A가 같은 표 뷰를 다시 열면, **Then** 조절한 너비가 유지된다.

---

### User Story 3 - 읽기 전용 사용자도 화면을 조정할 수 있다 (Priority: P3)

보기 권한만 있는 사용자도 자기 화면에서 그룹을 접고 열 너비를 조절할 수 있다. 이 조작은 보드 데이터를 바꾸지 않으므로 권한과 무관하게 허용된다.

**Why this priority**: P1·P2가 구현되면 자연스럽게 따라오는 개선이지만, 독립적으로 검증할 가치가 있는 사용자 경험 변화다.

**Independent Test**: 보기 권한만 가진 계정으로 표 뷰를 열고 그룹 접기와 열 너비 조절이 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 보기 권한만 있는 사용자가 표 뷰를 보고 있을 때, **When** 그룹 접기 버튼을 누르면, **Then** 자기 화면에서 그룹이 접히고 보드 데이터는 변하지 않는다.
2. **Given** 보기 권한만 있는 사용자가 표 뷰를 보고 있을 때, **When** 열 너비를 드래그하면, **Then** 자기 화면에서 너비가 바뀌고 보드 데이터는 변하지 않는다.

---

### Edge Cases

- 뷰에 이미 저장되어 있는 접힘·너비 값은 어떻게 되는가? → 개인 상태가 아직 없는 사용자에게 초기 기본값으로 보여 준다. 기존 저장값 자체는 삭제하거나 변경하지 않는다.
- 그룹의 기준이 되는 선택 옵션이 삭제되면? → 개인 상태에 남은 해당 그룹 항목은 무시되며 화면 동작에 영향을 주지 않는다.
- 브라우저가 개인 상태 저장을 허용하지 않는 환경(예: 시크릿 모드)에서는? → 현재 세션 안에서는 정상 동작하고, 재방문 시 유지만 되지 않는다. 오류를 사용자에게 노출하지 않는다.
- 뷰를 복제하거나 템플릿으로 보드를 만들면? → 개인 상태는 복제되지 않는다. 새 뷰는 뷰에 저장된 기본값으로 시작한다.
- 공유 구성인 "그룹 숨기기"와 개인 접힘 상태가 겹치면? → 숨겨진 그룹은 공유 규칙대로 모두에게 보이지 않고, 다시 보이게 되면 각 사용자의 개인 접힘 상태를 따른다.
- 실행취소(undo)와의 관계는? → 개인 화면 조작은 보드 변경 이력과 실행취소 대상에 포함되지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 표 뷰의 그룹 펼치기/접기는 조작한 사용자의 화면에만 적용되어야 하며, 같은 뷰를 보는 다른 사용자의 화면을 바꾸면 안 된다.
- **FR-002**: 표 뷰의 열 너비 조절은 조작한 사용자의 화면에만 적용되어야 하며, 같은 뷰를 보는 다른 사용자의 화면을 바꾸면 안 된다.
- **FR-003**: 그룹 펼치기/접기와 열 너비 조절은 공유 뷰 데이터를 변경하면 안 된다. 서버 저장, 실시간 방송, 보드 변경 이력, 실행취소 스택 어디에도 흔적을 남기지 않는다.
- **FR-004**: 사용자의 접힘·너비 상태는 같은 기기·같은 브라우저에서 보드를 다시 방문해도 유지되어야 한다.
- **FR-005**: 개인 상태가 아직 없는 사용자에게는 뷰에 저장되어 있는 기존 접힘·너비 값을 초기 기본값으로 보여 준다.
- **FR-006**: 보기 권한만 있는 사용자도 자기 화면에서 그룹 접기와 열 너비 조절을 할 수 있어야 한다.
- **FR-007**: 그룹(열) 숨기기/보이기, 정렬, 필터, 표시 속성, 계산식 등 나머지 뷰 구성은 기존처럼 모든 사용자에게 공유·동기화되어야 한다.
- **FR-008**: 개인 상태는 사용자와 뷰의 조합 단위로 구분되어야 한다. 같은 보드의 다른 뷰, 다른 보드의 뷰에 영향을 주면 안 된다.

### Key Entities

- **개인 뷰 표시 상태**: 사용자 × 뷰 조합마다 하나씩 존재하는 화면 조정 값의 묶음. 접힌 그룹 목록과 열별 너비를 담는다. 보드 데이터가 아니므로 다른 사용자와 공유되지 않고, 보드 권한의 지배를 받지 않는다.
- **공유 뷰 구성**: 뷰에 저장되어 모든 사용자에게 동일하게 적용되는 설정(그룹 숨김, 정렬, 필터, 표시 속성, 계산식 등). 이 기능의 변경 대상이 아니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 서로 다른 두 계정으로 같은 표 뷰를 열어 두고 한쪽에서 그룹 접기 또는 열 너비 조절을 10회 반복해도, 다른 쪽 화면은 한 번도 바뀌지 않는다.
- **SC-002**: 보기 권한만 있는 계정으로 그룹 접기와 열 너비 조절을 시도하면 100% 성공한다 (현재는 0%).
- **SC-003**: 접힘·너비를 조정한 뒤 같은 기기에서 보드를 다시 방문하면 조정한 상태가 그대로 재현된다.
- **SC-004**: 정렬·필터 등 공유 뷰 구성을 변경하면 기존처럼 같은 뷰를 보는 다른 사용자에게 수 초 안에 반영된다 (회귀 없음).
- **SC-005**: 그룹 접기·열 너비 조작 시 보드 변경 이력에 새 항목이 생기지 않는다.

## Assumptions

- 개인 상태의 유지 범위는 기기·브라우저 단위다. 같은 계정이라도 다른 기기에서는 상태가 공유되지 않으며, 계정 단위 동기화는 이번 범위에서 제외한다. (기존 개인 설정 선례와 같은 방식)
- 뷰에 이미 저장된 접힘·너비 값은 삭제하거나 이전하지 않는다. 개인 상태가 없는 사용자의 초기 기본값으로 계속 쓰이며, upstream 데이터 구조와의 호환을 유지한다.
- 공유 기본 너비·기본 접힘을 의도적으로 바꾸는 별도 기능은 제공하지 않는다. 이번 변경 이후 뷰에 저장된 값은 사실상 고정된 기본값 역할만 한다.
- 범위는 표 뷰로 한정한다. 칸반·갤러리·캘린더 뷰는 그룹 접힘·열 너비 개념을 사용하지 않으므로 해당 없음이다.
- 서버와 다른 클라이언트(API 등)가 뷰의 접힘·너비 값을 바꾸더라도, 이미 개인 상태를 가진 사용자의 화면은 영향을 받지 않는다.
