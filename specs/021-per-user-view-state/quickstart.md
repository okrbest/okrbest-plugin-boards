# 종단 검증 가이드: 표 뷰 개인 화면 제어 분리

구현 완료 후 이 시나리오를 실제 화면에서 확인하고 결과를 완료 근거로 제시한다 (constitution 원칙 I).

## 사전 준비

```bash
# 자동 빌드·배포 (켜져 있지 않으면)
cd webapp && setsid env MM_DEBUG=1 nohup npm run debug:watch > /tmp/boards-watch.log 2>&1 < /dev/null &

# 배포 확인 후 브라우저 하드 리프레시 필수 (자동 새로고침 없음)
```

- Mattermost: `http://localhost:8065`
- 계정 2개 필요: 보드 편집 권한 계정 A, 보기 권한만 있는 계정 B (없으면 `qa-account-via-local-mode` 메모 절차로 생성)
- 대상: 그룹이 있는 표 뷰 (예: FY27 OKR 보드의 표 뷰, 또는 아무 보드에 select 속성으로 groupBy 설정)
- 브라우저 창 2개를 나란히 띄우고 각 계정으로 같은 표 뷰를 연다

## 시나리오 1: 그룹 접기가 전파되지 않는다 (US1 / SC-001)

1. A 창에서 그룹 하나를 접는다.
2. **기대**: A 창에서만 접히고, B 창은 변화 없다.
3. B 창에서 다른 그룹을 접는다 — A 창은 변화 없다.
4. 브라우저 DevTools Network 탭 확인: 접기 조작 시 `PATCH /plugins/focalboard/api/v2/boards/.../blocks/...` 요청이 **발생하지 않아야** 한다.

## 시나리오 2: 열 너비가 전파되지 않는다 (US2 / SC-001)

1. A 창에서 열 하나의 너비를 드래그로 바꾼다.
2. **기대**: A 창에서만 바뀌고, B 창은 그대로다. PATCH 요청 없음.

## 시나리오 3: 재방문 시 유지된다 (SC-003)

1. A 창에서 그룹을 접고 열 너비를 바꾼 뒤 다른 보드로 이동했다가 돌아온다.
2. **기대**: 접힘·너비가 그대로다.
3. 브라우저 새로고침(F5) 후에도 유지된다 (localStorage 복원).

## 시나리오 4: 읽기 전용 사용자도 조작할 수 있다 (US3 / SC-002)

1. B(보기 권한) 창에서 그룹 접기 버튼을 누른다 — 접힌다.
2. B 창에서 열 너비를 드래그한다 — 바뀐다.
3. **기대**: 둘 다 B 화면에서만 동작하고 서버 요청·오류가 없다.
4. 대조: B 창에서 정렬 변경·그룹 숨기기 등 공유 구성 메뉴는 여전히 권한으로 막혀 있다.

## 시나리오 5: 공유 구성은 기존대로 동기화된다 (FR-007 / SC-004 회귀)

1. A 창에서 정렬을 바꾸거나 그룹을 숨긴다(그룹 헤더 메뉴 → Hide).
2. **기대**: 수 초 안에 B 창에도 반영된다.
3. A 창에서 카드 내용을 수정한다 — B 창에 실시간 반영된다.

## 시나리오 6: 기존 저장값이 기본값 역할을 한다 (FR-005)

1. 한 번도 조작하지 않은 계정(또는 localStorage를 비운 상태)으로 뷰를 연다.
2. **기대**: 뷰에 저장되어 있던 접힘·너비가 그대로 보인다.
3. localStorage 비우기: DevTools Console에서 `localStorage.removeItem('viewLocalState')` 후 새로고침.

## 시나리오 7: 변경 이력에 남지 않는다 (SC-005)

1. A 창에서 접기·너비 조작 후 Ctrl+Z(undo)를 누른다.
2. **기대**: 접힘·너비가 되돌려지지 않는다(undo 대상이 아님). 직전의 실제 데이터 변경이 있었다면 그것이 되돌려진다.

## 시나리오 8: 뷰 복제 시 개인 상태가 따라가지 않는다 (spec Edge Case)

1. A 창에서 그룹을 접어 둔 표 뷰를 복제한다(뷰 메뉴 → Duplicate view).
2. **기대**: 복제된 뷰는 뷰에 저장된 공유 값(복제 시점의 원본 뷰 저장값)으로 보이고, A의 개인 접힘·너비는 따라가지 않는다 (새 viewId라 개인 상태 키가 다르다).
